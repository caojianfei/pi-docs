用主题自定义 Pi ​

主题控制 Pi 在交互模式和 HTML 导出中使用的颜色。Pi 内置 system、dark 和 light 主题。你可以选择其中一个主题、跟随终端的浅色或深色外观，或创建自己的配色。

使用终端的颜色 ​

system 主题是默认主题。它基于终端的主题构建 Pi 的颜色，让 Pi 与终端保持一致，而不是自带配色：

  • Pi 查询终端的默认前景色、背景色及其 16 个 ANSI 颜色。
  • 每个 Pi 颜色的色相取自某个 ANSI 颜色，例如错误取红色、链接取蓝色。
  • Pi 调整每个颜色的明度，使其与背景保持最低对比度。正文文本在背景和每个面板上至少保持 4.5:1 的 WCAG 对比度。
  • 当终端在浅色和深色之间切换时，Pi 会重新查询颜色并重建主题。

主题会根据终端上报的内容进行适配：

终端上报内容结果
背景色和 ANSI 颜色来自终端调色板、并针对实际背景放置的颜色。
仅背景色Pi 自身的色相，并针对实际背景放置。
无ANSI 颜色索引和终端默认颜色，由终端自行渲染。次要文本较淡，面板无背景色。

Pi 在启动时向终端询问颜色。终端通常在几毫秒内应答，Pi 最多等待 100 毫秒后显示启动页眉。如果终端未及时应答，Pi 使用 ANSI 颜色回退；如果颜色稍后到达（例如通过慢速 SSH 连接），Pi 仍会应用它们。system 是保留名称：使用该名称的自定义主题会被忽略。

选择主题 ​

打开 /settings 并选择 Theme。你可以为所有终端外观使用同一个主题，也可以为浅色和深色终端分别选择主题。

所选内容保存为 theme 设置：

json
{
  "theme": "dark"
}

没有 theme 设置时，Pi 使用 system。

自动模式按先浅色、后深色的顺序存储：

json
{
  "theme": "light/dark"
}

Pi 根据终端上报的背景色和前景色判断终端是浅色还是深色。如果终端不上报背景色，Pi 依次使用终端的浅色/深色通知、COLORFGBG 环境变量，最后默认深色。同一判断既决定浅色/深色对中选用哪个主题，也决定 system 的外观。自动模式激活时，终端上报外观变化后 Pi 会切换主题。主题名称不能包含 /，因为 Pi 将其保留用于该设置的格式。

使用 --use-theme 在单次运行中选择初始主题，而不更改保存的设置：

bash
pi --use-theme light
pi --use-theme light/dark

命令行选项见 CLI 资源。

创建自定义主题 ​

复制一个内置主题，或创建一个符合模式（schema）的新 JSON 文件。内置主题使用 OKHSL 颜色，多个角色共享的颜色用变量表示，因此你可以直接调整色相、饱和度或明度。

  1. 将文件保存为 <agent-dir>/themes/my-theme.json。agent 目录默认为 ~/.pi/agent。
  2. 将其 name 设为 my-theme。
  3. 修改 vars 和 colors 中的值。
  4. 通过 /settings 选择 my-theme。

文件名使用主题名称。Pi 仅从 <agent-dir>/themes/<name>.json 热重载当前生效的用户主题。从其他来源添加或修改主题后，运行 /reload。

理解主题文件 ​

属性必需职责
$schema否根据 Pi 发布的 schema 启用编辑器校验和补全。
name是在选择器和设置中标识主题。必须唯一，不能包含 /，也不能是 system。
appearance否"dark" 或 "light"：主题设计的背景。省略时 Pi 从主题颜色推断。
vars否定义可复用的颜色值。变量可以引用其他变量。
colors是为终端 UI 角色分配颜色。schema 标明必需和可选角色。
export否覆盖 HTML 导出中的页面和面板背景。

主题对象是严格的：只接受文档中列出的顶层字段和颜色令牌（token）。可复用的自定义颜色定义在 vars 下；colors 或 export 下的自定义键以及其他顶层元数据会被拒绝。

颜色可以用六种形式书写：

形式示例含义
RGB 十六进制"#0af" 或 "#00aaff"三位或六位 sRGB 颜色。
OKLCH"oklch(62% 0.1 200)"感知明度、彩度和色相。
OKHSL"okhsl(250 60% 55%)"色相、饱和度和明度。饱和度相对于 sRGB 色域在该色相和明度下允许的最大值，因此每个值都在色域内，相同的饱和度看起来色彩程度相同。
256 色索引390 到 255 的 ANSI 调色板索引。
变量引用"primary"vars 中某个条目的值。
终端默认""终端的默认前景色或背景色。

终端默认颜色按终端自身的颜色渲染。当 Pi 需要具体值时（例如 HTML 导出或扩展的颜色计算），它使用终端上报的默认颜色，或根据主题外观猜测黑或白。

Pi 解析链式变量引用。缺失变量或循环引用会使主题无效。Pi 在可用时使用真彩色（truecolor），将 OKLCH 色域映射（gamut-map）到 sRGB，并为 256 色终端近似颜色。HTML 导出将 OKHSL 值转换为十六进制，因为 CSS 不支持它们。如果颜色与来源值不同，检查终端的真彩色检测和对比度设置。见配置终端。

确切的属性、必需颜色和接受的值类型见主题 JSON schema。

Pi 在启动时和 /reload 时报告无效的主题文件。

主题颜色描述的是界面角色，而不是单个组件。使用以下分组找到 schema 中的相关部分：

区域颜色名称

从项目或包加载主题 ​

项目主题放在 .pi/themes/ 中。项目主题只在授予项目信任后加载。

也可以通过 themes 设置加载主题文件和目录，或在 Pi 包中分发。见配置、设置和 Pi 包。

每个加载的主题必须名称唯一。Pi 将重复名称报告为资源冲突。
