Codemode ​

codemode 工具让模型编写 JavaScript 脚本，调用 pi 的其他工具并运行非 LLM 模型（如分类器和图像模型）。只有脚本的输出会到达模型，因此脚本可以并行执行调用，并在模型看到之前过滤大量结果。开启方法参见 启用 codemode。

脚本 ​

工具输入是原始 JavaScript 源码，不是 JSON，也不是 markdown 代码围栏。它作为 async 函数体在 QuickJS 沙箱中运行，因此顶层 await 和 return 都可用。沙箱没有 Node API、文件系统、网络或定时器；脚本只能通过工具和 models 访问外部世界。

脚本可以以选项行开头。选项行必须是第一行；出现在其他位置会导致调用在脚本运行前失败：

js
// @options: {"max_output_tokens": 2000, "timeout_ms": 60000}
  • max_output_tokens（默认 10000）限制输出。超长输出保留开头和结尾，完整文本写入临时文件，其路径包含在结果中。当输出的文本和 base64 图片数据超过 16777216 个字符，或 text()、image() 和 console 调用超过 100000 次时，脚本失败；请改用工具将大数据写入文件。
  • timeout_ms 是整个脚本的硬性截止时间，包括等待空闲 worker 的时间。默认不设置。图片生成可能耗时数分钟，因此生成图片的脚本不要设置过短的截止时间。

结果以 Script completed 或 Script failed 开头，随后是耗时和输出。文本和图片条目按顺序出现，各占一行。当输出包含多个文本条目（来自 text() 或 return）时，每个条目以 ==> text N/M <== 行开头。console 调用汇总在一个 <console_output> 块中，每次调用一行。失败的脚本保留其部分输出，后跟 Script error: 和错误信息。工具调用是真实的：失败前已发出的调用不会回滚。脚本结束时仍在运行的调用会被取消，未 await 的 promise 会被丢弃。

全局对象 ​

全局对象用途
tools.<name>(args)调用工具。参见 调用工具。
text(value)向输出添加文本条目。字符串原样添加，其他值转为 JSON。
image(value)向输出添加图片：base64 data: URL、{ image_url } 对象，或图片块 { type: "image", data, mimeType }（如 MCP 工具和 models.generateImages() 返回的）。不支持远程 URL。接受 PNG、JPEG、GIF 和 WebP。每张图片还会保存到临时文件，结果在图片之前给出路径。
console.log(...)在其他输出之后的 <console_output> 块中添加一行。参数以空格连接；info、warn、error 和 debug 行为相同。
return value顶层 return 会像 text() 一样添加该值。
exit()成功结束脚本。
store(key, value) / load(key)在多次 codemode 调用之间保存小的 JSON 值。参见 存储值。
ALL_TOOLS所有可调用工具的 { name, description }，包括描述中未列出的工具。
searchTools(query, { limit?, namespace? })按相关性对可调用工具排序（BM25，默认 limit 8）。解析为 { name, description }[]。
describeTool(name)解析为工具的描述和 TypeScript 声明，或 undefined。
describeNamespace(name)解析为某个命名空间（如 MCP 服务器）的 { name, description?, instructions?, tools }，或 undefined。
models列出并运行非 LLM 模型。参见 模型。

调用工具 ​

会话可以调用的每个工具都是 tools 的一个方法，以其标识符命名：JavaScript 标识符中不合法的字符会变成 _，因此 MCP 工具 mcp__dev-radius__search 对应 tools.mcp__dev_radius__search。每个方法接受一个包含该工具参数的对象。

调用的解析结果取决于工具：

  • 有输出 schema 的工具解析为结构化值。bash 解析为 { output, truncated, full_output_path?, exit_code, wall_time_seconds }，非零退出码时也是如此。其 output 不受模型可见的 2000 行或 50KB 限制：最多容纳 1 MiB，更长的输出保留首尾各 512 KiB，中间为省略标记，并设置 truncated，完整输出在 full_output_path 中。
  • MCP 工具解析为其 CallToolResult，包括 isError 和 structuredContent。
  • read 解析为文件文本；对图片则解析为图片块 { type: "image", data, mimeType, note }，可交给 image() 展示。data 是模型看到的 base64 图片，note 是随附文本（如缩放提示）。
  • 其他工具（如 edit 和 write）解析为其文本输出。

失败、被阻止或参数无效的调用会 reject 一个携带该工具错误文本的 Error。使用 Promise.allSettled() 保留成功调用的结果。

codemode 的描述按命名空间（例如单个 MCP 服务器）列出工具及其 TypeScript 声明。deferred 暴露方式的工具——包括默认 codemode 暴露方式下的 MCP 工具——不会被列出，因此 MCP 服务器连接时描述保持不变。已列出的声明共享 3000 估算 token 的预算（设置中的 codemode.inlineBudget）。脚本可通过 searchTools()、describeTool()、describeNamespace() 或过滤 ALL_TOOLS 找到其他工具。

codemode 激活时，设置中的 codemode.mode 决定其他工具的呈现方式。on（默认）时已声明的工具保持声明，其描述说明如何从脚本调用。only 时这些工具对模型隐藏，改为列在 codemode 的描述中，因此模型通过脚本调用它们。codemode 描述、describeTool() 和 ALL_TOOLS 中的工具声明会附带工具的提示词准则，因为系统提示词规则只覆盖已声明的工具。

存储值 ​

store(key, value) 在字符串键下保存 JSON 值，供后续 codemode 调用使用；存储 undefined 会删除该键。load(key) 返回值或 undefined。只有脚本成功时写入才会保留：每个成功存储值的脚本会向会话（session）追加一条 codemode-store 自定义条目，因此恢复的会话保留这些值，且每个分支（branch）只看到其路径上写入的值。

存储用于小状态，如 ID、游标或摘要。单个值最多 262144 个字符的 JSON，所有值合计最多 1048576。不要存储图片数据；用 image() 展示图片，它还会将图片保存到临时文件。

模型 ​

models 访问模型目录，并用会话的凭据运行非 LLM 模型：分类器（对 JSON 状态回答类型化问题，部分模型还支持图片）和图像模型（生成图片）。聊天模型会列出但不能从脚本运行。可用的分类器和图像模型参见 使用分类器模型 和 使用图像模型。

ts
type ModelType = "chat" | "image" | "classifier";

/** A catalog entry. `provider` and `id` identify it; other fields depend on the type. */
interface ModelInfo {
  type?: ModelType;
  provider: string;
  id: string;
  name: string;
  api: string;
  input: ("text" | "image")[];
  contextWindow?: number;
  [key: string]: unknown;
}

declare const models: {
  /** Every known model of a type, optionally for one provider. */
  getModelsOfType(type: ModelType, provider?: string): Promise<ModelInfo[]>;
  /** Models of a type whose provider has working credentials. */
  getAvailableOfType(type: ModelType, provider?: string): Promise<ModelInfo[]>;
  /** One catalog entry, or undefined. */
  getModelOfType(type: ModelType, provider: string, id: string): Promise<ModelInfo | undefined>;
  /** Answer `context.questions` about `context.state`; answers are in `result.answers` by question ID. */
  classify(model: ModelInfo, context: ClassifierContext): Promise<ClassifierResult>;
  /** Generate images from `context.input` text and image blocks; show `result.output` blocks with image(). Can take minutes. */
  generateImages(model: ModelInfo, context: ImagesContext): Promise<ImagesResult>;
};

classify() 和 generateImages() 只使用 model 的 provider 和 id，因此 { provider, id } 也可以。它们不会在提供商（provider）出错时抛出异常：请检查 stopReason 和 errorMessage。每个脚本最多同时运行四个此类调用；更多调用会等待空闲槽位，因此对大量条目使用 Promise.all() 没问题。它们的用量会计入 codemode 工具结果，并计入会话成本。

模型 ID 在不同提供商之间不同，例如 typesafe/jev-latest 和 openrouter/typesafe/jev-1.13。使用 models.getAvailableOfType(type) 查找当前凭据可用的 ID。

分类 ​

ts
interface ClassifierContext {
  /** The data to classify. */
  state: Record<string, unknown>;
  /** Images judged together with `state`. Only models whose `input` includes "image" accept them. */
  images?: { type: "image"; data: string; mimeType: string }[];
  /** Questions by ID. One call answers all of them. */
  questions: Record<string, ClassifierQuestion>;
}

type ClassifierQuestion =
  /** Pick one label. `criteria` maps each label to what it means. */
  | { type: "choice"; instructions: string; criteria: Record<string, string> }
  /** Score on an ordered scale. `criteria` describes each level, lowest first. */
  | { type: "score"; instructions: string; criteria: string[] }
  /** Yes or no. */
  | { type: "bool"; instructions: string; criteria: { true: string; false: string } };

interface ClassifierResult {
  provider: string;
  model: string;
  /** Answers by question ID. */
  answers: Record<string, ClassifierAnswer>;
  usage?: ModelUsage;
  stopReason: "stop" | "error" | "aborted";
  errorMessage?: string;
}

type ClassifierAnswer =
  | { type: "choice"; choice: string; probabilities: Record<string, number>; confidence: number }
  /** `score` is the expected level index, from 0 to `criteria.length - 1`. */
  | { type: "score"; score: number; confidence: number }
  /** Probability of `true`. */
  | { type: "bool"; probability: number };

/** Token counts and cost in USD, when the service reports them. */
type ModelUsage = { input: number; output: number; totalTokens: number; cost: { total: number } };

对多个条目分类时，为每个条目调用一次 classify()。以下脚本对反馈消息排序，例如脚本早前由工具返回的消息：

js
const jev = await models.getModelOfType("classifier", "typesafe", "jev-latest");
const results = await Promise.all(
  messages.map((message) =>
    models.classify(jev, {
      state: { message },
      questions: {
        sentiment: {
          type: "choice",
          instructions: "How does the user feel about the product?",
          criteria: { positive: "Satisfied or happy", negative: "Unhappy or frustrated", neutral: "Neither" },
        },
        urgency: {
          type: "score",
          instructions: "How urgently does this need a reply?",
          criteria: ["no reply needed", "reply this week", "reply today"],
        },
      },
    }),
  ),
);
return results.map((result, i) =>
  result.stopReason === "stop"
    ? { message: messages[i], sentiment: result.answers.sentiment.choice, urgency: result.answers.urgency.score }
    : { message: messages[i], error: result.errorMessage },
);

input 包含 "image" 的分类器也会判断图片。tools.read() 将图片文件返回为 images 接受的图片块。当 images 非空时，其他分类器返回错误结果。

js
const luna = await models.getModelOfType("classifier", "openai", "gpt-6-luna");
const photo = await tools.read({ path: "screenshot.png" });
const result = await models.classify(luna, {
  state: { task: "Settings page redesign" },
  images: [photo],
  questions: {
    broken: {
      type: "bool",
      instructions: "Does the screenshot show a broken layout?",
      criteria: { true: "Overlapping, cut-off, or misaligned elements", false: "Clean layout" },
    },
  },
});

生成图片 ​

ts
interface ImagesContext {
  /** The prompt as text blocks, plus image blocks to edit or use as references. */
  input: (TextBlock | ImageBlock)[];
}

interface ImagesResult {
  provider: string;
  model: string;
  /** Generated images, and text blocks for models that also return text. */
  output: (TextBlock | ImageBlock)[];
  usage?: ModelUsage;
  stopReason: "stop" | "error" | "aborted";
  errorMessage?: string;
}

type TextBlock = { type: "text"; text: string };
/** `data` is base64. */
type ImageBlock = { type: "image"; data: string; mimeType: string };

用 image(block) 展示生成的图片。不要用 text()、console 或 return 打印 data：它很大，且模型无法将其作为文本阅读。image() 还会将每张图片保存到临时文件并在结果中给出路径，因此后续轮次可以复制或移动该文件。

js
// @options: {"timeout_ms": 300000}
const painter = await models.getModelOfType("image", "openrouter", "google/gemini-2.5-flash-image");
const result = await models.generateImages(painter, {
  input: [{ type: "text", text: "A red fox in the snow, watercolor" }],
});
if (result.stopReason !== "stop") return result.errorMessage;
for (const block of result.output) {
  if (block.type === "image") image(block);
  else text(block.text);
}

限制 ​

  • 脚本的虚拟机有 256 MB 内存。耗尽时抛出 InternalError: out of memory；请过滤或聚合大数据，而不是累积它。
  • 在 Bun 上，停止脚本或到达截止时间会及时结束调用，但不轮询 QuickJS 中断处理器的内置函数可能在其 worker 中继续计算直到返回。
  • 一个 pi 进程中所有会话最多同时存在两个 codemode worker；PI_CODEMODE_MAX_WORKERS 可修改该限制。被取消的 worker 在退出前占据其槽位。达到上限时，新脚本按到达顺序等待空闲 worker。60 秒内（或其 timeout_ms 之前）未获得 worker 的脚本会直接失败，不会运行。
  • 等待一个永远无法 settle 的 promise（且没有待处理的工具调用）的脚本会立即失败，因为没有定时器。
  • 脚本不能启动其他 codemode 脚本。
