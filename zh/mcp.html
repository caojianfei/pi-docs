MCP 服务器 ​

Pi 通过 stdio 或 streamable HTTP 连接到 Model Context Protocol 服务器，并使其工具和资源对模型可用。

快速设置 ​

添加一个本地 stdio 服务器，检查连接，然后启动 Pi：

bash
pi mcp add filesystem -- npx -y @modelcontextprotocol/server-filesystem .
pi mcp list
pi

远程服务器：

bash
pi mcp add docs --url https://example.com/mcp --bearer-token-env-var DOCS_TOKEN
pi mcp list

这些命令默认添加用户级（user-level）服务器。添加 --local 或 -l 则写入项目配置：

bash
pi mcp add -l tools --env API_KEY='${TOOLS_KEY}' -- uvx tools-mcp

在交互会话中用 /mcp 检查连接、登录、重连、更改暴露（exposure）方式，或启用、禁用服务器。在会话外添加、删除或更改服务器后运行 /reload。

配置服务器 ​

Pi 从 ~/.pi/agent/mcp.json 读取用户级服务器，从 .pi/mcp.json 读取项目服务器。项目配置只有在授予项目信任后才会被读取。同名时项目条目会覆盖用户级条目。

没有 command、url 或 type 的项目条目只覆盖同名用户级服务器的 enabled、exposure 和 toolExposure，保留其余内容，包括 env、headers 和 auth。例如，以下配置在一个项目中关闭某个用户级服务器：

json
{
  "mcpServers": {
    "internal-tools": { "enabled": false }
  }
}

格式与其他 MCP 客户端一致：

json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "."]
    },
    "docs": {
      "url": "https://example.com/mcp",
      "headers": { "Authorization": "Bearer ${DOCS_TOKEN}" },
      "description": "Search and read the product documentation"
    }
  }
}

Stdio 服务器使用 command、args、env 和 cwd。相对 cwd 值相对于会话目录解析。command、参数或 cwd 中以 ~/ 开头表示用户主目录。

HTTP 服务器使用 url、headers 和 oauth（参见使用 OAuth 认证）。不支持旧的 SSE 传输（transport）。

两类服务器都支持：

  • timeout：每次请求的超时秒数（默认 60）。进度通知会重置它。
  • enabled: false：保留条目但不连接。
  • exposure 和 toolExposure：控制工具以何种方式到达模型（参见控制工具暴露）。
  • description：用一句话说明服务器提供什么。它会在系统提示词中列出该服务器（参见控制工具暴露），工具搜索按它对服务器工具排序，codemode 的 describeNamespace() 会返回它。未设置时，服务器连接后使用服务器指令的第一行。

个人服务器和带凭据的服务器放在用户级文件中。项目文件只用于项目所需的服务器，且仅限受信任的项目。

配置规则 ​

  • 服务器名只能包含字母、数字、_ 和 -。工具命名为 mcp__<server>__<tool>，除字母、数字和 _ 外的每个字符都替换为 _；替换后重名的服务器工具都会加哈希后缀。仅在 - 和 _ 上不同的服务器名视为同一服务器：第二个会被拒绝，且 mcp.json 中的服务器会覆盖已注册的服务器。
  • type 可选。command 选择 stdio，url 选择 streamable HTTP。如果提供，type 必须是 stdio、http 或 streamable-http。
  • 拒绝 sse。文档中提供 SSE 端点的服务器通常也提供 streamable HTTP，通常位于 /mcp 而不是 /sse。
  • command 是一个可执行文件，args 包含其参数。它不是 shell 命令字符串。
  • env 和 headers 的值可以使用环境变量如 ${GITHUB_TOKEN}。也可以用 !command 执行命令，但命令必须构成整个值，例如 "Authorization": "!echo Bearer $(gh auth token)"。
  • 无效条目会被报告并跳过，不会阻止其他服务器连接。

pi mcp add 和 pi mcp remove 覆盖 shell 中的常见变更。各选项参见 MCP 命令。

检查或修改服务器 ​

/mcp 列出已配置的服务器及其状态、工具数量、暴露方式和配置来源。需要关注的服务器排在前面。选择一个服务器可以查看其工具和连接详情、重连、登录或登出、更改暴露方式，或启用、禁用它。

暴露和启用状态变更会保存到定义该服务器的文件中，不会替换无关内容。在受信任的项目中，"Enable in this project" 和 "Disable in this project" 会为用户级服务器添加项目覆盖；此后对该服务器的变更都会保存到覆盖项中。禁用的服务器仍会列出。在交互 TUI 之外，/mcp 打印服务器状态；/mcp login <server>、/mcp logout <server> 和 /mcp reconnect <server> 直接执行对应操作。

Shell 命令无需会话即可使用：pi mcp add、pi mcp remove、pi mcp list、pi mcp login 和 pi mcp logout。Shell 命令不加载扩展。

诊断连接问题 ​

运行 pi mcp list 连接每个已启用的服务器并打印其状态、工具和错误。当条目无效或某个已启用服务器未连接时，它以状态码 1 退出。/mcp 显示完整连接错误和失败的 stdio 服务器的 stderr 末尾内容。

Pi 在启动后一次性报告配置错误、连接失败和需要登录的服务器。服务器的日志通知追加到 ~/.pi/agent/mcp.log，格式为 <time> [<server>] <level> <logger>: <message>。文件超过 5 MB 后移动到 mcp.log.1。

会话启动时，Pi 在后台连接每个已启用的服务器。服务器工具在其连接后出现；codemode 描述不列出它们，因此不会随服务器连接而变化。第一个提示词最多等待 10 秒，且只等待带有 direct 工具的服务器，因为这些工具必须在其请求中声明。其他服务器在需要时等待：codemode 脚本等待其指定的服务器（mcp__<server>），并在调用 searchTools() 或读取 ALL_TOOLS 时等待全部；tool_search 和资源工具也等待全部。HTTP 网络错误和瞬态状态（408、429 和 5xx）重试两次。连接断开时显示为 disconnected，并在下次调用时重连。当服务器宣布工具列表变化时，新工具被添加，撤回的工具变得不可用。

停止 stdio 服务器时，Pi 关闭其 stdin，发送 SIGTERM，然后对其进程组发送 SIGKILL。这也会停止通过 npx 或 uvx 等包装器启动的服务器。

从其他客户端迁移配置 ​

把转换后的条目移动到 mcp.json 的 mcpServers 下，然后运行 pi mcp list 验证。

客户端转换方式
Claude Desktop、Claude Code 或 Cursor复制现有的 mcpServers 条目。
VS Code从顶层 servers 对象移动条目，并把 ${input:...} 提示替换为 ${NAME} 环境变量。
Codex把 [mcp_servers.<name>] TOML 字段（如 command、args、env 和 url）转换为 JSON。
OpenCode把 "type": "local" 转换为 stdio 条目，把其 command 数组拆分为 command 和 args，把 environment 重命名为 env，并把 {env:NAME} 替换为 ${NAME}。把 "type": "remote" 转换为 URL 条目。

使用 OAuth 认证 ​

使用 OAuth 的远程服务器（如 Sentry）不需要在 mcp.json 中配置凭据：

json
{
  "mcpServers": {
    "sentry": { "url": "https://mcp.sentry.dev/mcp" }
  }
}

当服务器拒绝未认证的连接时，/mcp 显示需要登录。选择 "Sign in"，运行 /mcp login sentry 或 pi mcp login sentry。Pi 打开授权页面并等待批准。如果浏览器在另一台机器上运行（例如通过 SSH），将其重定向后的 URL 粘贴到登录界面。正在运行的会话在其下一轮使用新凭据。

Pi 向授权服务器注册自己，把令牌存储在 ~/.pi/agent/mcp-auth.json，并在令牌过期或被服务器拒绝时刷新访问令牌。如果服务器稍后请求额外的 scope，Pi 会再次要求登录。登出会删除已存储的凭据。

凭据属于服务器名和 URL 的组合。相同 URL 但名称不同的服务器（例如每个账户一个）分别登录；不同 mcp.json 文件中同名同 URL 的服务器共享一次登录。

OAuth 适用于没有 Authorization 头的 HTTP 服务器。对于不支持动态客户端注册（dynamic client registration）的服务器，配置一个已注册的客户端：

json
{
  "mcpServers": {
    "example": {
      "url": "https://mcp.example.com/mcp",
      "oauth": { "clientId": "my-client", "clientSecret": "${EXAMPLE_SECRET}", "callbackPort": 8765 }
    }
  }
}

重定向 URI 必须与注册的 URI 一致。callbackPort 使用 http://127.0.0.1:<port>/callback。要使用其他 URI，设置 callbackUrl；它必须在 localhost、127.0.0.1 或 [::1] 上使用 HTTP。Pi 原样发送它。当 callbackUrl 省略端口时，Pi 使用 callbackPort 或空闲端口并将其加入 URI，这是 RFC 8252 允许的 loopback 重定向方式。clientSecret 可选，可以使用环境变量或命令。

对于不声明所需 scope 的服务器，将 scope 设置为空格分隔的列表。否则，Pi 请求服务器声明的 scope。之后的 scope 请求会追加到配置值上。

Pi 以 pi 注册。有些服务器只接受来自已知客户端的注册。设置 clientName 以发送其他名称：

json
{
  "mcpServers": {
    "figma": { "url": "https://mcp.figma.com/mcp", "oauth": { "clientName": "Claude Code" } }
  }
}

该名称只在 Pi 注册客户端时发送。要以新名称重新注册，先登出。

有些授权服务器通过 Client ID Metadata Document URL 允许客户端而不是注册它们。设置 clientRegistration 为 cimd，以 pi.dev 上的 Pi 文档标识自己而不是注册：

json
{
  "mcpServers": {
    "example": { "url": "https://mcp.example.com/mcp", "oauth": { "clientRegistration": "cimd" } }
  }
}

客户端 ID 为 https://pi.dev/oauth/client.json，重定向 URI 为 http://127.0.0.1:<port>/callback。如果授权服务器未在授权响应中发送 iss 参数（RFC 9207），Pi 会改用针对该 MCP 服务器的文档和重定向路径：https://pi.dev/oauth/<id>/client.json 和 http://127.0.0.1:<port>/callback/<id>。授权服务器必须声明支持 Client ID Metadata Document 和公共客户端（public clients），否则登录失败。cimd 不能与 clientId 或 clientName 同时使用，且 callbackUrl 必须使用 localhost 或 127.0.0.1，路径为 /callback。

Pi 通过服务器的受保护资源元数据（RFC 9728）找到授权服务器，并检查授权服务器的元数据指明预期的 issuer（RFC 8414）。有些服务器声明了错误或缺失的授权服务器，导致登录打开不存在的页面。将 authServerMetadataUrl 设置为正确授权服务器的元数据文档：

json
{
  "mcpServers": {
    "example": {
      "url": "https://mcp.example.com/mcp",
      "oauth": { "authServerMetadataUrl": "https://example.okta.com/.well-known/openid-configuration" }
    }
  }
}

Pi 使用该文档而不是发现机制，并按配置信任它，因此只指向你信任的文档。URL 必须使用 HTTPS，localhost、127.0.0.1 或 [::1] 除外。

控制工具暴露 ​

每个服务器工具注册为 mcp__<server>__<tool>。服务器的 exposure 决定模型以何种方式使用它：

暴露方式行为典型用途
codemode（默认）可从 codemode 脚本调用，但既不向模型声明，也不在 codemode 描述中列出。脚本通过 searchTools()、describeTool() 或 ALL_TOOLS 查找工具。通用 MCP 服务器，尤其是需要脚本组合或过滤调用的场景。
deferred在 tool_search 为下一次模型调用加载到匹配项之前不声明。大型服务器，其工具应在发现后直接调用。
direct像内置工具一样向模型声明，也可以从 codemode 调用。小型、常用的工具集。
hidden已注册但不可用。应保持不可用的服务器或工具。

codemode-deferred 作为 codemode 的别名被接受。

带有 codemode 或 deferred 工具的服务器会列在系统提示词的 mcp_servers 部分，包含其工具的到达方式，以及配置的 description 中的一行（连接后为服务器指令中的一行）。Pi 在提示词开始时更新该部分，此前会等待带有 direct 工具的服务器。当该部分发生变化时——例如某服务器连接后其摘要变为可用——Pi 会将新部分追加到对话中而不是修改工具声明，以保持较早消息的缓存。describeNamespace() 和 searchTools() 的 namespace 选项接受 mcp__dev-radius、mcp__dev_radius、dev-radius 或 dev_radius。

当 codemode 暴露的服务器连接时，Pi 激活 codemode。对 deferred 暴露的服务器激活 tool_search。要让模型无需搜索就能看到某个工具，用 toolExposure 给它 direct 暴露。

toolExposure 为单个工具覆盖服务器暴露方式。键是精确的服务器工具名或模式，* 匹配任意字符。精确名优先于模式；模式之间首个匹配生效。hidden 暴露的服务器只能暴露选定的工具：

json
{
  "mcpServers": {
    "github": {
      "url": "https://api.githubcopilot.com/mcp/",
      "exposure": "deferred",
      "toolExposure": {
        "search_code": "direct",
        "get_*": "codemode",
        "delete_*": "hidden"
      }
    }
  }
}

pi mcp list 会标记暴露方式与服务器不同的工具。/mcp 的 Tools 视图也显示生效的暴露方式。

codemode 或 deferred 暴露的工具可以通过任一间接机制访问：codemode 脚本可以调用它们，tool_search 也可以加载它们。Codemode 调用不依赖当前激活的工具集，因此在 /tree、resume 和 fork 之后仍然可用。tool_search 加载的工具记录在会话记录（transcript）中，并在该分支上保持声明。

--tools 不会移除 MCP 工具，除非其某个条目以 mcp__ 开头；pi --tools read,codemode,'mcp__radius__*' 只保留 radius 的工具。--exclude-tools 接受相同的模式，--no-mcp 在一次运行中禁用 MCP（参见工具）。

要在没有 MCP 服务器的情况下保持 codemode 激活，在设置中添加 "defaultTools": ["+codemode"]。要防止 codemode 自动激活，在 mcpServers 旁设置 "autoEnableCodemode": false。项目值覆盖用户级值。当 codemode 和 tool_search 都未激活且非 direct 工具无法调用时，Pi 警告一次。

超过 20 KB 的文本结果到达模型时，其中间部分被移除，并以 …N chars truncated… 标记代替。完整文本保存到结果中指明的临时文件。Codemode 脚本收到完整结果，可在向模型返回输出前进行缩减。

Codemode 脚本收到完整的 MCP CallToolResult，包括 content、structuredContent 和 isError。带 isError 的结果在脚本内正常解析，但对直接调用会报告为错误。image(result.content[0]) 转发图像块。服务器指令不属于任何工具描述；脚本通过 describeNamespace("mcp__<server>") 读取它们，该调用也返回服务器的工具名。

使用资源 ​

当已连接的服务器提供资源时，Pi 添加 Codex 和 OpenCode 使用的资源工具：

  • list_mcp_resources 以 JSON 列出资源：{ server?, resources: [{ server, uri, name, ... }], nextCursor? }。带 server 时列出一页；cursor 继续下一页。不带 server 时列出所有服务器的所有资源。
  • list_mcp_resource_templates 列出服务器未直接列出的资源的 URI 模板。
  • read_mcp_resource 按 server 和 uri 读取资源。文本以文本形式到达模型，图像以图像形式。其他二进制资源保存到临时文件，模型收到路径。脚本收到 { server, uri, contents }。

这些工具到达每个启用的、非 hidden 的有资源服务器。它们的暴露方式取这些服务器中最宽的暴露：direct，然后是 codemode 或 deferred。工具结果中的资源链接标识 read_mcp_resource 和对应的服务器。

MCP Apps 的资源（以 ui:// URI 或 text/html;profile=mcp-app 标识）被省略，因为 Pi 不渲染它们。资源图标同样省略。

读取和列出资源在瞬态 HTTP 错误（408、429 或 5xx）后重试一次。工具调用不重试，因为服务器可能已经执行了它们。

权限 ​

每次 MCP 调用都经过 Pi 的工具管线。因此扩展的 tool_call 和 tool_result 处理器（包括权限门控）也适用于 MCP 工具。从 codemode 脚本发起的调用以 parentToolCallId 携带 codemode 调用 ID。

pi.getAllTools() 报告每个服务器声明的注解（annotations）：readOnlyHint、destructiveHint、idempotentHint 和 openWorldHint。权限扩展可以使用这些提示决定哪些调用需要确认（参见工具暴露）。资源工具标记为只读。

扩展与 SDK ​

从扩展添加服务器 ​

扩展可以用 pi.registerMcpServer(name, config) 为当前会话添加服务器，使用与 mcpServers 条目相同的结构（参见扩展中的 MCP 服务器）。注册的服务器像配置的服务器一样连接，并出现在 /mcp 中，来源显示为该扩展。

对启用状态或暴露方式的变更只作用于当前会话。同名文件配置的服务器优先，/mcp 列出被覆盖的注册。pi mcp shell 命令不加载扩展，只看到文件配置的服务器。

替换内置 MCP 支持 ​

已安装的注册 /mcp 的扩展（如 pi-mcp-adapter）会在会话中替换内置 MCP 支持。此时 Pi 不读取 mcp.json，也不在会话中连接其服务器，/mcp 属于该扩展。移除该扩展可恢复内置行为。要在没有替代的情况下禁用内置 MCP 支持，在 pi config 的 Built-in 下禁用 mcp，或在设置中设置 "extensions": ["-builtin:mcp"]。--no-mcp 在一次运行中禁用它。

注册 codemode 或 tool_search 的扩展同样以该名称替换内置工具。Pi 为 MCP 服务器激活替代工具，并且仅当其声明了 reachesTools 时才等待其调用需要的服务器。Shell 级的 pi mcp 命令始终使用内置实现。

从 SDK 使用 MCP ​

SDK 会话不加载内置扩展。将 MCP 扩展、用于 codemode 服务器的 codemode 扩展，以及用于 deferred 服务器的工具搜索扩展加入资源加载器。参见 Codemode 与 MCP。
