选择模型 ​

对于内置提供商（provider），先运行 /login，再用 /model 选择模型。只有当 Pi 尚未内置你需要的提供商或端点时，才使用自定义模型配置。

选择连接方式 ​

你拥有的条件推荐做法
受支持的订阅通过 /login 登录
提供商的 API key通过 /login 保存，或设置其环境变量
本地 GGUF 模型将 Pi 连接到 llama.cpp 路由器
OpenAI、Anthropic 或 Google 兼容端点添加到 models.json
使用自定义协议或认证流程的提供商构建或安装提供商扩展

浏览模型目录可查看当前的提供商、模型 ID、能力、上下文限制和定价。Pi 启动时使用内置目录，并可以用 pi.dev 的较新目录数据覆盖。缓存的目录数据离线仍可用；运行 pi update --models 可强制刷新。

身份验证 ​

运行 /login 并选择一个提供商。Pi 将凭据保存在 auth.json 中。运行 /logout 可移除某个提供商已保存的凭据。

你也可以通过提供商的环境变量提供 API key。这在 CI 以及其他不应由 Pi 写入凭据的环境中很有用。提供商列出了各环境变量和对应的提供商设置。

当配置了多个凭据来源时，Pi 优先使用运行时的 --api-key，然后是已保存的 auth.json 凭据、models.json 中的 apiKey，最后是提供商的环境变量或环境云凭据。提供商扩展可以定义自己的认证行为。

请妥善保管 auth.json 和任何凭据命令。在你信任某个项目之后，项目设置和扩展可以在 Pi 进程内执行。在从不受信任的目录加载配置之前，请先阅读安全。

选择模型 ​

运行 /model 可搜索可用模型。选择器只显示其提供商具备可用认证的模型。在某个模型上按 Ctrl+S 可将其保存为新会话的默认模型。

运行 /thinking 可选择当前模型的思考级别（thinking level）。在那里按 Ctrl+S 可保存启动时的级别。Pi 会将选项限制为所选模型支持的级别。

Ctrl+P 可在可用模型之间循环切换。使用 /scoped-models 控制该循环并保存选择，或通过设置配置模型模式。

会话会记录模型和思考级别的变更。恢复会话时会还原这些设置，而不会更改新会话的默认值。

连接本地模型 ​

Pi 与 llama.cpp 路由器直接集成。路由器会发现 GGUF 文件并按需加载模型。Pi 的 /llama 命令管理路由器，/model 则从其已加载的模型中选择。

服务器启动、模型布局、下载和连接排障请参见使用 llama.cpp 运行本地模型。

对于 Ollama、LM Studio、vLLM、SGLang 和其他兼容服务器，请在 models.json 中配置兼容端点。

配置兼容端点 ​

当端点使用 Pi 已支持的 API 时，使用 models.json。这包括大多数 Ollama、LM Studio、vLLM、SGLang 和代理部署。

json
{
  "$schema": "https://pi.dev/schemas/models.schema.json",
  "providers": {
    "ollama": {
      "baseUrl": "http://localhost:11434/v1",
      "api": "openai-completions",
      "apiKey": "ollama",
      "models": [
        { "id": "qwen2.5-coder:7b" }
      ]
    }
  }
}

这个占位 key 使模型对 Pi 可用；Ollama 会忽略它。对于需要认证的端点，apiKey 和 header 值可以使用 $NAME 或 ${NAME} 环境变量插值、字面值，或以 !command 开头的命令。$$ 和 $! 分别产生字面量 $ 和 !。models.json 中的命令在请求时运行，Pi 不会缓存其结果。

打开 /model 时会重新加载该文件。models 条目会在该提供商上添加或替换同 ID 的模型。使用 modelOverrides 可修改现有内置模型或扩展提供的模型的元数据，而无需替换该提供商的模型列表。未知的覆盖 ID 会被忽略。

要让内置提供商经由代理访问，只需设置其 baseUrl。其模型和认证保持不变：

json
{
  "providers": {
    "anthropic": { "baseUrl": "https://proxy.example.com/v1" }
  }
}

模型配置列出了所有字段。

描述模型输入与缓存 ​

使用 inputLimits.images.resize 控制 Pi 在将新图片附件、read 结果和工具结果中的图片存入会话历史之前如何编码：

json
{
  "id": "vision-model",
  "input": ["text", "image"],
  "inputLimits": {
    "images": {
      "resize": {
        "maxWidth": 1568,
        "maxHeight": 1568,
        "maxBytes": 524288,
        "jpegQuality": 75
      }
    }
  }
}

maxBytes 限制 base64 编码后的载荷。省略的 resize 字段使用保守默认值：2000×2000 像素、编码后 4.5 MiB、JPEG 质量 80。图片只编码一次；更换模型不会重写历史图片。目录还可以通过 inputLimits.maxRequestBytes、images.maxPerMessage 和 images.maxPerRequest 描述硬性请求限制，但 Pi 尚未据此重写或拒绝历史。

使用 promptCache 声明提供商在 short 或 long 保留层级下尽力而为（best-effort）的缓存生存期（秒）：

json
{ "id": "claude-sonnet-5", "promptCache": { "short": 300, "long": 3600 } }

选择已公布范围中保守的一端。模型在当前层级没有生存期时，不参与缓存预热（cache warming）。modelOverrides 条目可以为内置或扩展模型设置 inputLimits 或 promptCache，包括通过经验证的代理访问的模型。参见 cacheWarming。

按思考级别配置采样 ​

OpenAI 兼容 API 支持自由格式的 samplingParams 模型默认值，以及 samplingParamsByThinkingLevel 覆盖。后者使用 Pi 的思考级别键（off、minimal、low、medium、high、xhigh 和 max），而不是 thinkingLevelMap 中的提供商值：

json
{
  "id": "qwen-thinking-model",
  "reasoning": true,
  "samplingParams": {
    "temperature": 1.0,
    "top_p": 0.95
  },
  "samplingParamsByThinkingLevel": {
    "off": {
      "temperature": 0.7,
      "top_p": 0.8
    },
    "high": {
      "top_k": 20
    }
  }
}

Pi 会先将不支持的思考级别收敛（clamp）到支持范围，然后按顺序合并模型 samplingParams、生效级别的覆盖值和请求级 samplingParams。同一键以后面的值为准。缺失的级别继承模型默认值。modelOverrides 会逐键将各级别条目与基础模型合并。这些字段仅适用于 openai-completions、openai-responses 和 azure-openai-responses；其他 API 会忽略它们。

兼容性设置应当描述端点在请求或响应行为上已验证的差异。不要仅因为端点宣称兼容 OpenAI 或 Anthropic 就启用它们。

使用分类模型 ​

分类模型（classifier model）不进行对话。它们回答关于 JSON 状态的类型化问题：从若干选项中选一个、回答是或否，或给出一个分数，每项都带概率。Pi 包含来自这些提供商的 TypeSafe Jev 模型、来自 Workers AI 和 OpenRouter 的 Cloudflare Clef、Clef Flash 和 Clef Omni 模型，以及通过 Decisions API 提供的 OpenAI GPT-6 Luna：

提供商模型 ID认证
typesafejev-latestTYPESAFE_API_KEY
openroutertypesafe/jev-1.13, typesafe/jev-1.14, ~typesafe/jev-latest, cloudflare/clef, cloudflare/clef-flash, cloudflare/clef-omniOPENROUTER_API_KEY 或 /login
cloudflare-workers-aitypesafe/jev, typesafe/jev-1.14.0, @cf/cloudflare/clef, @cf/cloudflare/clef-flash, @cf/cloudflare/clef-omniCLOUDFLARE_API_KEY 和 CLOUDFLARE_ACCOUNT_ID
vercel-ai-gatewaytypesafe-ai/jevAI_GATEWAY_API_KEY
opencodejev-1.13, jev-1.13-freeOPENCODE_API_KEY
openaigpt-6-lunaOPENAI_API_KEY

llama.cpp 路由器上的对话模型也会被列为分类模型。

OpenAI 的 Decisions API 需要 API key。使用 ChatGPT 凭据登录的方式不适用于它，因此当 openai 通过 /login 登录时，即使设置了 OPENAI_API_KEY，gpt-6-luna 也不会显示为可用；请先登出 openai 以使用该 key。该 API 拒绝超过 922K token 的输入，但运行超过约 5 秒的请求（目前约为 600K 输入 token 以上）会因网关超时而失败。

分类模型不出现在 /model 中。模型通过 codemode 工具访问它们，该工具默认关闭，除非某个 MCP server 开启了它。在设置中使用 "defaultTools": ["+codemode"] 启用。之后脚本可以用 models.getAvailableOfType("classifier") 列出分类模型，并调用 models.classify(model, { state, questions })：

js
const jev = await models.getModelOfType("classifier", "typesafe", "jev-latest");
const result = await models.classify(jev, {
  state: { message: "The change works, thanks." },
  questions: {
    approved: {
      type: "bool",
      instructions: "Does the user approve of the result?",
      criteria: { true: "Approval", false: "No approval" },
    },
  },
});
return result.answers;

Codemode 描述了问题和答案的类型。

input 包含 "image" 的分类模型还会判断通过 images 传入的图片；其他分类模型对图片返回错误。图片输入适用于 GPT-6 Luna、来自 typesafe 和 cloudflare-workers-ai 的 Jev、来自 cloudflare-workers-ai 的 Clef，以及目录中列出支持图片输入的 OpenRouter 模型。Jev 接受 PNG 和 JPEG 图片，在 TypeSafe 自有 API 上图片输入仍属实验性。Clef 接受 PNG、JPEG 和 WebP 图片，每次请求最多四张。来自 vercel-ai-gateway 和 opencode 的 Jev 只接受文本。

每个 System One 服务使用各自的请求格式接收图片，由模型的 compat.imageInput 指定。内置模型已设置该字段，因此覆盖提供商的 baseUrl 不会影响它。代理其他服务分类器的自定义提供商应在 models.json 的提供商级 compat 中设置（参见 System One 兼容性）。尤其是 OpenRouter，它会以 TypeSafe 的格式应答且不报错，但会丢弃图片。

当服务报告 token 计数时（所有 System One 服务都会），result.usage 会携带计数及其费用。Pi 会将脚本分类器调用的用量累加到 codemode 工具结果中，因此会计入页脚和 /session 中的会话费用。费用使用模型目录价格；没有目录价格的模型（如 TypeSafe 直连的 jev-latest）只报告 token 而不计费。

扩展通过 ctx.modelRegistry.classify() 调用分类器，无需 codemode。虚拟模型可以用它们路由请求；参见 jev-router.ts 示例。

使用图像模型 ​

图像模型根据提示词和可选的输入图片生成图像。Pi 在 openrouter 提供商下列出 OpenRouter 的图像模型，例如 google/gemini-2.5-flash-image 和 black-forest-labs/flux.2-pro；它们与其对话模型使用相同的 OPENROUTER_API_KEY 或 /login 凭据。

与分类模型一样，图像模型不出现在 /model 中；模型通过 codemode 工具访问它们。脚本用 models.getAvailableOfType("image") 列出它们，并调用 models.generateImages(model, { input })。结果的 output 包含 base64 图片块，image() 会将其附加到 codemode 结果中，使模型能看到：

js
const painter = await models.getModelOfType("image", "openrouter", "google/gemini-2.5-flash-image");
const result = await models.generateImages(painter, {
  input: [{ type: "text", text: "A red fox in the snow, watercolor" }],
});
if (result.stopReason !== "stop") return result.errorMessage;
for (const block of result.output) if (block.type === "image") image(block);

input 还可以包含 { type: "image", data, mimeType } 块，用于编辑或作为参考。与分类器调用一样，Pi 会将脚本图像调用的用量累加到 codemode 工具结果中。生成的图片不会保存到磁盘。Codemode 描述了完整 API。

扩展通过 ctx.modelRegistry.generateImages() 生成图像，无需 codemode。

添加自定义提供商 ​

当提供商需要自定义流式传输、模型发现或认证行为时，使用扩展。扩展工作流参见自定义提供商。

故障排查 ​

模型未出现 ​

确认其提供商具有可用的认证。自定义模型可以从 models.json 加载，但在 Pi 能解析凭据之前，它们在 /model 中仍不可用。对于 llama.cpp，只显示路由器当前已加载的模型。

认证只在一个 shell 中有效 ​

检查 key 是否来自环境变量而非 auth.json。环境变量必须存在于启动 Pi 的进程中。

登录在远程机器上打开浏览器 ​

如果提供商支持，完成其无界面（headless）认证流程。一些提供商允许你将最终重定向 URL 或授权码粘贴回 Pi。参见交互式认证。

兼容端点拒绝请求 ​

检查 models.json 中该端点的 API 类型和兼容性设置。上游服务器必须支持相应的请求字段和行为。
