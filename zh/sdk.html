SDK ​

@earendil-works/pi-coding-agent 将 Pi 嵌入 Node.js 或 Bun 进程。它提供对命令行应用所用的 agent、会话、工具、模型和资源的直接 TypeScript 访问。

需要进程内 TypeScript 集成时使用 SDK。需要与语言无关或隔离的子进程时，请参见 CLI 集成。

typescript
import { createAgentSession } from "@earendil-works/pi-coding-agent";

const { session } = await createAgentSession();

try {
  await session.prompt("What files are in the current directory?");
  console.log(session.getLastAssistantText());
} finally {
  session.dispose();
}

它会使用工作目录、发现的资源、已存储的设置和已配置的凭据。prompt() 在运行结束时解析（resolve）。

最简完整示例还会流式输出文本事件。所有 SDK 示例都与仓库一起做了类型检查。

会话生命周期 ​

createAgentSession() 创建一个 AgentSession。会话拥有一个对话及其模型和工具、排队中的消息、压缩（compaction）状态和扩展运行时。

通过 session.messages、session.model、session.thinkingLevel、session.systemPrompt 和 session.getActiveToolNames() 读取当前状态。

session.systemPrompt 是只读的，返回当前生效的系统提示词，包括尚未发送给模型的更改。工具更改会在下一次请求之前声明给模型。

会话存储 ​

会话默认是持久化的。SessionManager 拥有持久化或内存中的条目树，并跟踪其活跃叶子（active leaf）。分支（branch）操作改变该叶子，但不删除被放弃的分支。当 Pi 重建模型上下文时，管理器会选择活跃分支并应用压缩。

SessionManager 是最终化模型上下文的权威来源。要恢复外部历史，请在构造会话时传入包含这些条目的管理器。给 session.agent.state.messages 赋值不会替换持久化上下文。

当宿主不想要会话文件时，使用内存中的管理器：

typescript
import { createAgentSession, SessionManager } from "@earendil-works/pi-coding-agent";

const { session } = await createAgentSession({
  sessionManager: SessionManager.inMemory(),
});

创建、打开、继续、列出和分叉会话，请参见带类型检查的会话示例。会话文件格式定义了持久化的 JSONL 契约，消息类型定义了对话记录中的值。要查看确切的方法和签名，请使用导出的 TypeScript 声明或 session-manager.ts。

cwd 选择用于项目资源发现、上下文文件、会话分组和内置工具路径的工作区。当目标目录与 process.cwd() 不同时应显式传入。

session.dispose() 会中止进行中的工作、使扩展上下文失效、断开与 agent 的连接并移除事件监听器。会话不再需要时请调用它。

AgentSessionRuntime 增加了 newSession()、switchSession()、fork() 和 importFromJsonl()。每个操作都会替换活跃的 AgentSession，并为目标工作目录重建服务。

运行时替换之后，原有的订阅属于旧的 AgentSession，必须重新绑定。参见会话运行时示例。

提示词 ​

prompt() 会处理扩展命令，并在普通用户消息进入 agent 之前展开基于文件的提示词模板。对于被接受的 agent 运行，它在运行结束后解析，包括自动重试。

当会话已在流式输出时发送的提示词，必须指定是要引导（steer）当前运行还是在其后跟随。不指定而调用 prompt() 会被拒绝，而不是自动猜测。

引导消息在当前助手轮次及其工具调用之后进入。后续（follow-up）消息在当前运行完成其待处理工作之后进入。steer() 和 followUp() 直接暴露这两种行为：如果输入被排队（包括经过扩展转换之后），返回 "queued"；如果被扩展消费，返回 "handled"。

abort() 停止活跃操作并等待会话变为空闲。waitForIdle() 只等待而不中止。

订阅事件 ​

宿主需要流式输出时，应在发送提示词之前订阅：

typescript
const unsubscribe = session.subscribe((event) => {
  if (event.type === "message_update" && event.assistantMessageEvent.type === "text_delta") {
    process.stdout.write(event.assistantMessageEvent.delta);
  }
});

try {
  await session.prompt("Explain this repository");
} finally {
  unsubscribe();
}

会话事件报告消息更新、工具执行、队列、压缩、重试和运行生命周期变化。

message_end 包含权威的已完成消息。agent_end 标志一次低层 agent 运行的结束，但自动恢复或排队的工作仍可能随后发生。

当宿主需要确认 Pi 不会自动继续时，使用 agent_settled。

配置会话 ​

不提供覆盖项时，工厂会创建 ModelRuntime、基于文件的 SettingsManager、持久化的 SessionManager、DefaultResourceLoader 以及已配置的默认工具。

每个边界都可以显式提供：

  • modelRuntime、model、thinkingLevel 和 scopedModels 控制模型的访问和选择。
  • settingsManager 提供合并后的设置或内存中的配置。
  • sessionManager 提供持久化或内存中的对话历史。
  • resourceLoader 提供扩展（extension）、技能（skill）、提示词模板、主题和上下文文件。
  • tools、noTools、excludeTools 和 customTools 控制活跃的工具集。

想要标准发现机制加上部分覆盖时，使用 DefaultResourceLoader。当宿主完全拥有资源存储和发现机制时，提供自定义的 ResourceLoader。

内联扩展工厂可以通过 DefaultResourceLoader 提供。只有当它需要在诊断信息和启动输出中有稳定名称时，才给它一个 InlineExtension 名称。带 replaceable: true 的命名内联扩展，在其他扩展在加载期间注册了同名工具、命令或 flag 时会被排除，而不是两者都加载并产生冲突。CLI 内置的 codemode、tool search 和 MCP 扩展都是可替换的。带 builtin: true 的命名条目不是内联扩展：它提供 builtin:<name> 扩展的代码，其加载方式类似于已配置的扩展文件。它默认加载，列在 pi config 中，可以通过 extensions 设置中的 -builtin:<name> 或 noExtensions 禁用；additionalExtensionPaths: ["builtin:<name>"] 可以显式加载它。它在项目信任（project trust）解析完成之后加载，因此无法处理 project_trust。CLI 的内置扩展就使用它。

CLI 将 codemode、tool_search 和 MCP 作为内置扩展加载。SDK 会话不会；请把 createCodemodeExtension()、createToolSearchExtension() 和 createMcpExtension() 加入 DefaultResourceLoader 的 extensionFactories。codemode 和 tool_search 注册时处于未激活状态：通过 defaultTools 设置启用它们（["+codemode", "+tool_search"] 保留其他默认工具），或者让 MCP 扩展激活它们：带 codemode 暴露的服务器启用 codemode，带 deferred 暴露的服务器启用 tool_search。MCP 扩展在 session_start 时连接其服务器，因此请调用 session.bindExtensions()。参见 Codemode 与 MCP。

更多聚焦示例请参见模型、工具、扩展和完全控制。
