命令行 ​

本页记录 Pi 内置的命令行命令与选项。运行 pi --help，或在命令后附加 --help，可查看你安装版本的确切接口。顶层帮助还包含已加载扩展注册的选项。

sh
pi [options] [--] [@files...] [messages...]
pi install <source> [options]
pi remove <source> [options]
pi uninstall <source> [options]
pi update [target] [options]
pi list
pi config [options]
pi auth <check|print-api-key|print-bearer-token> [options]
pi mcp <add|remove|list|login|logout> [options]

调用与输出 ​

sh
pi
pi --print "Summarize this repository"
git diff | pi --print "Review this change"
pi --mode json "Inspect this repository" > events.jsonl

当 stdin 和 stdout 都是终端时，除非 --print、--mode json 或 --mode rpc 选择了其他界面，否则 Pi 会打开终端 UI。当任一流被重定向且未选择 JSON 或 RPC 模式时，Pi 使用打印（print）模式。关于如何在交互、print、JSON、RPC 和 SDK 集成之间选择，参见 CLI 集成。

输入行为
message提供初始提示词
@path在第一条提示词中包含一个文本文件或图片
管道 stdin将其内容前置到第一条提示词
--停止选项解析，使提示词可以以 - 开头

Pi 从当前工作目录解析 @path。工作目录还决定项目配置、资源发现和会话分组。

--print 控制 Pi 是否运行一次后退出。--mode 选择输出界面。当 stdin 和 stdout 都是终端时，--mode text 不会强制一次性执行；需要该行为请使用 --print。

选项行为
-p, --print运行给定提示词，将最终助手文本写入 stdout，然后退出
--mode text选择文本输出；当 stdin 和 stdout 是终端时仍会打开终端 UI
--mode json运行给定提示词，将 JSONL 事件写入 stdout，然后退出
--mode rpc从 stdin 读取 JSONL 命令，将响应和事件写入 stdout，直到关闭
--export <input> [output]将会话文件导出为 HTML 后退出；省略 output 时自动推导目标路径

RPC 模式拒绝 @file 参数。JSON 和 RPC 模式将 stdout 保留给协议记录。参见 JSON 事件流 和 RPC 协议。

模型 ​

sh
pi --model sonnet:high

模型选择参见 选择模型，凭据参见 提供商。

  • --provider <name>
    将 --model 的查找限定到单个提供商（provider）。必须与 --model 一起使用。
  • --model <pattern>
    按精确 ID 或模糊 ID/名称匹配选择。接受 provider/id 和可选的 :<thinking> 后缀。若多个提供商匹配，Pi 优先选择有凭据的那个，否则要求提供 --provider。
  • --api-key <key>
    使用非持久化的 API key 覆盖。必须配合通过 --model 或 --models 选择的模型使用。它不会在多个提供商提供同一模型时进行选择。
  • --thinking <level>
    设置 off、minimal、low、medium、high、xhigh 或 max。它会覆盖 --model 后缀，并被限制在模型能力范围内。
  • --models <patterns>
    为启动和循环切换设置逗号分隔的范围。接受精确 ID、模糊匹配、大小写不敏感的 glob，以及可选的 :<thinking> 后缀。多个提供商都提供的模型会为每个提供商各添加一条，并给出警告。
  • --list-models [search]
    列出可用模型，可按模糊搜索过滤，然后退出。

会话 ​

sh
pi --continue

继续、分叉（fork）、命名和存储会话参见 会话与上下文。

  • -c, --continue
    继续当前项目最近一次的会话（session）。
  • -r, --resume
    打开会话选择器。
  • --session <path|id>
    按文件路径、精确 ID 或部分 ID 打开。Pi 先搜索当前项目，若匹配到跨项目会话会提示是否分叉。
  • --session-id <id>
    打开精确的项目会话 ID，不存在则创建。ID 可包含字母、数字、.、_ 和 -。
  • --fork <path|id>
    将现有会话分叉为当前项目的新会话。
  • --session-dir <dir>
    覆盖存储和查找位置。优先于 PI_CODING_AGENT_SESSION_DIR 和 sessionDir 设置。
  • --no-session
    使用不持久化的内存会话。
  • -n, --name <name>
    设置会话显示名称。

约束：

  • 会话 ID 必须以字母或数字开头和结尾。
  • --fork 不能与 --session、--continue、--resume 或 --no-session 同时使用。
  • --session-id 不能与 --session、--continue 或 --resume 同时使用。可与 --fork 组合以指定新 ID。

工具 ​

sh
pi --tools read,grep,find,ls --print "Review this project"

配置默认工具选择参见 设置。

  • -t, --tools <list>
    用逗号分隔的允许列表（allowlist）替换默认选择，可包含内置、扩展（extension）或自定义工具。条目为工具名或模式，其中 * 匹配任意字符。MCP 工具默认保留，除非某条目以 mcp__ 开头（参见 MCP 工具）。仅由 +name 和 -name 条目组成的列表不是允许列表，而是修改默认选择。
  • -xt, --exclude-tools <list>
    在所有其他选择选项之后禁用逗号分隔的工具名或模式，包括 MCP 工具。
  • -nbt, --no-builtin-tools
    禁用默认内置工具，同时保留扩展和自定义工具。
  • -nt, --no-tools
    启动时禁用所有内置、扩展、自定义和 MCP 工具。

默认启用的工具是 read、bash、edit 和 write，除非 defaultTools 修改了它们。--tools 使用普通名称时会替换整个选择，因此需要列出每一个想要的工具。与 defaultTools 一样，它也接受仅由 +name 和 -name 条目组成的列表，用于向默认选择添加或移除工具：pi --tools +codemode,-write 保留其他默认工具，启用 codemode，禁用 write。这类条目只接受精确工具名，不接受 * 模式；要按模式禁用工具请使用 --exclude-tools。普通名称与 +name/-name 条目不能混用。/reload 会启用新加入 defaultTools 的工具，但用 -name 移除的工具保持移除状态。

--tools 选择向模型声明的工具。它不会移除 MCP 工具，MCP 工具的可用范围由其暴露方式（exposure）决定：pi --tools read,codemode 仍可从 codemode 脚本调用每一个 MCP 工具。没有条目命名或匹配到的 MCP 工具永远不会被直接声明，无论其暴露方式如何；只有 tool_search（若在列表中）可以加载它。一旦某个条目以 mcp__ 开头，--tools 也会过滤 MCP 工具，因此下面只保留 radius 服务器的工具：

sh
pi --tools read,bash,codemode,'mcp__radius__*'

MCP 资源工具（list_mcp_resources、list_mcp_resource_templates、read_mcp_resource）也算作 MCP 工具。要移除 MCP 工具，请使用 --exclude-tools 'mcp__*' 或 --no-mcp。

内置用途
read读取文本文件和支持的图片
bash运行 shell 命令
powershell在 Windows 上运行 PowerShell 命令
edit对现有文件应用精确文本替换
write创建或覆盖文件
grep搜索文件内容
find使用 glob 模式查找路径
ls列出目录内容

内置扩展额外提供两个工具。它们默认关闭；当 MCP 服务器需要时会由 MCP 扩展开启（参见 MCP）。要自行启用，可在 --tools 或 defaultTools 中列出它们。

内置扩展用途
codemode运行调用其他工具的 JavaScript，例如用 Promise.allSettled 并行执行；只有脚本的输出会到达模型
tool_search搜索未向模型声明的工具（codemode 和 deferred 暴露方式，如 MCP 工具），并为下一次调用声明匹配结果

启用 codemode ​

要为每个会话开启 codemode，将其添加到 ~/.pi/agent/settings.json 或项目 .pi/settings.json 的默认工具中：

json
{
  "defaultTools": ["+codemode"]
}

这会保留 read、bash、edit 和 write 并添加 codemode。单次调用可用 --tools 添加：

sh
pi --tools +codemode

Codemode 不依赖 MCP 也很有用：脚本可以并行运行多个工具调用，在大量输出到达模型前先做过滤，通过 models.classify() 调用 TypeSafe 的 Jev 等分类器模型（参见 分类器模型），并通过 models.generateImages() 生成图片（参见 图像模型）。

codemode 的工作方式 ​

脚本在 QuickJS 沙箱中运行，通过 tools.<name>(args) 访问其他工具。Codemode 描述了脚本 API、工具如何列出和查找、store() 和 models 全局对象，以及相关限制。

工具搜索 ​

tool_search 默认关闭；用 "defaultTools": ["+tool_search"] 或 --tools 启用。它对尚未声明的工具使用与 searchTools() 相同的排序，并为下一次模型调用声明匹配结果。已加载的工具会像其他工具变更一样记录到会话中，因此在该分支（branch）上保持声明状态。

资源 ​

sh
pi --extension ./review.ts

约定目录和项目信任参见 配置，配置的路径参见 设置，包来源参见 Pi 包。

  • -e, --extension <path>
    加载扩展文件或目录，或内置扩展（如 builtin:mcp），可重复使用。
  • -ne, --no-extensions
    禁用发现的、配置的和内置的扩展。显式的 -e 路径仍会加载，因此 pi -ne -e builtin:mcp 只保留内置 MCP 支持。
  • --no-mcp
    在本次运行中禁用内置 MCP 支持：不连接任何服务器，也没有 MCP 工具和 /mcp。它不影响替换了内置 MCP 支持的扩展。
  • --skill <path>
    加载技能（skill）文件或目录，可重复使用。
  • -ns, --no-skills
    禁用发现的和配置的技能。显式的 --skill 路径仍会加载。
  • --prompt-template <path>
    加载提示词模板文件或目录，可重复使用。
  • -np, --no-prompt-templates
    禁用发现的和配置的模板。显式的 --prompt-template 路径仍会加载。
  • --theme <path>
    加载主题文件或目录，可重复使用。
  • --use-theme <name[/name]>
    选择本次运行的初始交互主题。
  • --no-themes
    禁用发现的和配置的主题。显式的 --theme 路径仍会加载。
  • -nc, --no-context-files
    禁用 AGENTS.md 和 CLAUDE.md 的发现。

资源路径仅对当前进程生效。相对路径从当前工作目录解析。

提示词与进程 ​

sh
pi --append-system-prompt ./instructions.md

已保存的配置参见 配置，项目信任参见 安全，进程控制参见 环境变量。

  • --system-prompt <text|path>
    用文本或现有文件的内容替换默认系统提示词。
  • --append-system-prompt <text|path>
    将文本或现有文件追加到系统提示词，可重复使用。
  • --tui-mode <mode>
    使用 fullscreen（默认）或 regular 终端模式。
  • --verbose
    显示详细的交互启动信息，覆盖 quietStartup。
  • -a, --approve
    对此进程信任项目本地的配置和资源。
  • -na, --no-approve
    对此进程忽略受信任门槛限制的项目本地配置和资源。
  • --offline
    禁用自动网络活动，包括模型目录刷新。等同于 PI_OFFLINE=1。
  • -h, --help
    显示帮助，包括已加载扩展注册的 flag，然后退出。
  • -v, --version
    显示 Pi 版本，然后退出。

扩展可以注册额外的长选项。未知的短选项会被拒绝。

更新 Pi 或包 ​

不带目标运行 pi update 会更新 Pi 本身。

任务命令
更新 Pipi update
更新所有已安装的包pi update --extensions
更新某个已安装的包pi update <source>
刷新模型目录pi update --models
更新 Pi 和所有已安装的包pi update --all

当所选更新包含 Pi 时，加 --force 可重新安装 Pi。

当 Pi 由其他包管理器提供时（如 Nix），pi update 无法更新 Pi。请用该包管理器更新，例如 nix profile upgrade pi。包和模型目录的更新仍然可用。

别名与命令选项 ​

  • pi uninstall <source> 是 pi remove <source> 的别名。
  • pi update --self、pi update self 和 pi update pi 是 pi update 的别名。
  • pi update --extension <source> 是 pi update <source> 的别名。
  • -a, --approve 对单条命令信任项目本地文件。-na, --no-approve 忽略受信任门槛限制的项目本地文件。
  • 在命令后附加 -h 或 --help 可查看其确切用法和选项约束。

凭据命令 ​

sh
pi auth check --provider openai --json

认证命令需要 --provider <provider> 或 --model <model>。支持的方法参见 提供商。

命令描述
pi auth check输出 ready、not_ready 或 invalid；退出码分别为 0、1、2
pi auth print-api-key输出解析后的 API key
pi auth print-bearer-token输出解析后的 OAuth bearer token
选项适用范围描述
--provider <provider>全部为某个提供商解析凭据
--model <model>全部从某个模型解析凭据；可与 --provider 组合
--jsonauth check以 JSON 输出结构化结果
--credentialsauth check就绪时输出解析后的凭据
--no-refreshauth check不刷新已过期的 OAuth 凭据；默认会刷新
--min-expiry <duration>print-bearer-token要求剩余 token 有效期，单位为 ms、s、m 或 h，如 30m

输出凭据的命令会将机密写入 stdout。

MCP 命令 ​

这些命令可在会话之外运行，因此 agent 可以通过 bash 执行它们。参见 MCP 服务器。

命令描述
pi mcp add <server> [options] -- <command> [args...]在 mcp.json 中添加或替换 stdio 服务器；--env KEY=VALUE（可重复）和 --cwd <dir> 设置其环境变量和工作目录。命令之后的参数会传给它
pi mcp add <server> [options] --url <url>添加或替换 streamable HTTP 服务器；--header KEY=VALUE（可重复）、--bearer-token-env-var <NAME>（发送 Authorization: Bearer ${NAME}）、--oauth-client-id、--oauth-client-secret、--oauth-callback-port 和 --oauth-client-name 用于配置认证
pi mcp remove <server>从 mcp.json 中移除服务器；已存储的 OAuth 凭据保留
pi mcp list [--json]连接每个已启用的服务器并输出其状态、工具和错误；当某个配置条目无效或某个已启用的服务器未连接时以 1 退出
pi mcp login <server> [--timeout <seconds>]登录 OAuth 服务器：打开授权页面并等待浏览器；终端也接受粘贴的重定向 URL。--timeout 限制整个登录过程，包括对授权服务器的请求（默认 300 秒）
pi mcp logout <server>删除服务器的已存储 OAuth 凭据

add 和 remove 修改 ~/.pi/agent/mcp.json；加 --local（-l）时修改当前目录的 .pi/mcp.json。add 还接受 --exposure <mode>（参见 暴露方式）和 --description <text>，且不会连接；运行 pi mcp list 检查服务器。

项目 .pi/mcp.json 文件只对已受信任的项目读取。
