配置终端 ​

现代终端大多无需额外设置即可配合 Pi 使用。当修饰键、滚动、链接、图片、颜色或输入法编辑器（IME）候选窗位置表现异常时，请参考本页。

Pi 使用扩展按键协议（extended-key protocol），使终端能够把 Shift+Enter、Alt+Enter 等组合键与普通 Enter 区分开。终端代理、多路复用器和 IDE 内置终端可能更改或丢弃这些信息。

排查 ​

症状从这里开始
Shift+Enter 直接提交而不是插入换行下方对应终端的章节；tmux 见在 tmux 中运行 Pi
Alt+Enter 无法排队后续消息WezTerm、Alacritty 或 Windows Terminal
全屏模式滚动异常缓慢iTerm2
链接可用但不显示悬停预览Ghostty
未检测到内联图片或颜色覆盖检测到的能力
IME 候选窗位置错误WezTerm 或 IntelliJ IDEA
修饰键仅在 tmux 内失效在 tmux 中运行 Pi

使用 /hotkeys 查看 Pi 当前生效的快捷键。修改方法见快捷键。

Kitty ​

Kitty 无需额外配置即可支持所需的键盘协议。

iTerm2 ​

常规终端模式无需额外配置。

修复全屏滚动缓慢 ​

在全屏模式下，Pi 接管视口（viewport），iTerm2 会发送鼠标滚轮报告而不是滚动终端自身的历史记录。此时快速触控板手势每次只能移动大约一行。

要改变这一行为：

  1. 打开 iTerm2 > Settings > Advanced。
  2. 搜索 Trackpad scrolls fast?。
  3. 将其设置为 No。

这是 iTerm2 的全局设置，也可能改变原生触控板滚动行为。底层问题见 iTerm2 issue 9619。

Apple Terminal ​

Pi 在可用时会启用增强按键上报。如果 Terminal.app 对 Shift+Enter 仍发送普通 Return，Pi 会使用 macOS 本地的修饰键回退机制，将其识别为 Shift+Enter。

该回退仅在 Pi 与 Terminal.app 运行在同一台 Mac 上时有效。当 Pi 通过 SSH 运行在另一台机器上时，无法读取本地修饰键状态。

Ghostty ​

如果 Alt+Backspace 不生效，在 Ghostty 配置中添加以下映射：

text
keybind = alt+backspace=text:\x1b\x7f

配置文件位于 macOS 的 ~/Library/Application Support/com.mitchellh.ghostty/config 和 Linux 的 ~/.config/ghostty/config。

较旧的 Claude Code 配置中可能包含：

text
keybind = shift+enter=text:\n

这会发送原始换行符（linefeed），Pi 无法将其与 Ctrl+J 区分。如果添加该映射只是为了兼容旧版 Claude Code，请将其删除。Pi 已将 Ctrl+J 绑定为换行替代，因此该映射看似有效，实际上却会阻止 Pi 和 tmux 收到真正的 Shift+Enter 事件。

在全屏模式中打开链接 ​

全屏模式下链接仍可点击，但在 Pi 捕获鼠标输入时，Ghostty 不会显示常规的悬停下划线或 URL 预览。按住 macOS 上的 Shift+Command 或 Linux 上的 Shift+Ctrl 即可使用 Ghostty 的原生链接处理。

WezTerm ​

WezTerm 通常通过 xterm 扩展按键上报 Shift+Enter。要显式启用 Kitty 键盘协议，创建 ~/.wezterm.lua：

lua
local wezterm = require 'wezterm'
local config = wezterm.config_builder()
config.enable_kitty_keyboard = true
return config

在 macOS 上转发 Alt+Enter ​

WezTerm 在 macOS 上默认将 Option+Enter 绑定为全屏。要将其用于 Pi 的后续消息队列，在 config.keys 表中添加以下条目：

lua
{
  key = 'Enter',
  mods = 'ALT',
  action = wezterm.action.SendString('\x1b[13;3u'),
}

一个完整的极简配置为：

lua
local wezterm = require 'wezterm'
local config = wezterm.config_builder()
config.keys = {
  {
    key = 'Enter',
    mods = 'ALT',
    action = wezterm.action.SendString('\x1b[13;3u'),
  },
}
return config

在 WSL 中定位 IME 候选窗 ​

如果 CJK 输入法候选窗在 WSL 中不跟随 Pi 的文本光标，显示硬件光标：

bash
export PI_HARDWARE_CURSOR=1
pi

也可以在 Pi 设置中将 showHardwareCursor 设为 true。

Alacritty ​

Alacritty 通常能上报 Shift+Enter。在 macOS 上，Option+Enter 可能以普通 Enter 的形式到达。将以下内容添加到 ~/.config/alacritty/alacritty.toml，将其转发给 Pi：

toml
[[keyboard.bindings]]
key = "Enter"
mods = "Alt"
chars = "\u001b[13;3u"

修改文件后重启 Alacritty。

VS Code 集成终端 ​

VS Code 1.109.5 及更新版本默认在集成终端中启用 Kitty 键盘协议。

对于较旧版本，在 keybindings.json 中添加 Shift+Enter 终端绑定：

json
{
  "key": "shift+enter",
  "command": "workbench.action.terminal.sendSequence",
  "args": { "text": "\u001b[13;2u" },
  "when": "terminalFocus"
}

用户级 keybindings.json 通常位于：

  • macOS: ~/Library/Application Support/Code/User/keybindings.json
  • Linux: ~/.config/Code/User/keybindings.json
  • Windows: %APPDATA%\\Code\\User\\keybindings.json

Zed 集成终端 ​

在 Zed 的 keymap.json 中添加以下绑定：

json
{
  "context": "Terminal",
  "bindings": {
    "shift-enter": ["terminal::SendText", "\u001b[13;2u"],
    "ctrl--": ["terminal::SendText", "\u001b[45;5u"],
    "ctrl-alt-]": ["terminal::SendText", "\u001b[93;7u"]
  }
}

Windows Terminal ​

Windows Terminal 使用 Pi 的 Windows 和 WSL 快捷键默认值。完整列表见快捷键。

转发 Shift+Enter ​

按 Ctrl+Shift+, 或通过 Settings > Open JSON file 打开 Windows Terminal 的 settings.json。在 actions 数组中添加以下对象：

json
{
  "command": { "action": "sendInput", "input": "\u001b[13;2u" },
  "keys": "shift+enter"
}

完全关闭并重新打开 Windows Terminal，然后验证 Shift+Enter 在 Pi 中插入新行。

将 Alt+Enter 用于后续消息 ​

Windows Terminal 默认将 Alt+Enter 绑定为全屏。因此 Pi 在 Windows 和 WSL 上使用 Ctrl+Q 发送后续消息。

要改用 Alt+Enter，请配置 Windows Terminal 转发该按键，并在 Pi 的 keybindings.json 中将 app.message.followUp 绑定到 alt+enter。见快捷键。

xfce4-terminal 与 Terminator ​

这些终端无法可靠地区分修饰的 Enter 键与普通 Enter，因此 Ctrl+Enter 或 Shift+Enter 等自定义绑定可能无法工作。

需要这些快捷键时，请使用支持现代扩展按键的终端，例如 Kitty、Ghostty、WezTerm、iTerm2、Windows Terminal 或兼容的 Alacritty 版本。

IntelliJ IDEA 集成终端 ​

IntelliJ IDEA 内置终端无法可靠区分 Shift+Enter 与普通 Enter。请使用 Ctrl+J 换行，或在支持现代扩展按键的终端中运行 Pi。

如果 IME 候选窗不跟随文本光标，显示硬件光标：

bash
export PI_HARDWARE_CURSOR=1
pi

覆盖检测到的能力 ​

Pi 自动检测 OSC 8 超链接、内联图片协议和真彩色（truecolor）支持。终端代理或多路复用器可能使检测结果不准确。

能力环境变量设置
超链接PI_HYPERLINKS=1|0|autoterminal.hyperlinks: true|false|"auto"
内联图片PI_IMAGE_PROTOCOL=kitty|iterm2|none|autoterminal.images: "kitty"|"iterm2"|false|"auto"
真彩色PI_TRUE_COLOR=1|0|autoterminal.trueColor: true|false|"auto"

设置优先于环境变量。未设置或 auto 保持自动检测。

只强制使用整个终端路径都支持的能力。不支持的转义序列可能破坏渲染。规范取值定义见环境变量和设置。

程序状态 ​

Pi 通过程序状态协议（OSC 7501）上报自身状态，使终端和 agent 仪表盘可以显示它是在工作、等待你、已完成还是失败：

状态时机
working一次 agent 运行或压缩（compaction）正在进行。消息为会话名。
blocked扩展对话框或登录正在等待你。消息为对话框标题。
done一次运行完成。消息为会话名。
error一次运行以错误结束且不会重试。消息为错误的第一行。
idlePi 已启动，或你取消了运行。

上报内容不包含提示词或模型输出。Pi 只在终端应答协议的支持查询后才发送；tmux 和 screen 不转发这些信息。设置 PI_PROGRAM_STATUS=1 可以不询问直接发送，或设为 PI_PROGRAM_STATUS=0 关闭上报。
