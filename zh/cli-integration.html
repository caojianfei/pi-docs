CLI 集成 ​

默认情况下，运行 pi 会打开交互式终端界面。当输入或输出被管道或重定向时，Pi 改用打印（print）模式。你也可以在脚本和应用中显式选择 print、JSON 或 RPC 模式。

所有四种模式使用相同的 agent、会话（session）、资源和工具。模式决定输入如何进入 Pi、输出如何暴露，以及进程是否保持可用以接收更多命令。

SDK 不是一种 CLI 模式。它将 agent 直接嵌入 Node.js 或 Bun 进程。当直接使用 TypeScript 比跨进程边界更合适时，参见 SDK。

选择模式 ​

模式界面生命周期适用场景
交互（Interactive）终端 UI直到用户退出有人在直接使用 Pi
打印（Print）stdout 上的最终文本单次调用脚本只需要最终助手响应
JSONstdout 上的 JSONL 事件单次调用进程需要一次运行的结构化进度
RPCJSONL 命令、响应和事件长驻进程需要双向控制

CLI 选项仍然独立于模式选择工作目录、模型、工具、资源和会话持久化。完整的启动选项参见 命令行。

打印到 stdout ​

打印模式运行给定提示词，将最终助手文本写入 stdout，然后退出：

bash
pi --print "Summarize the changes in this repository"

当只需要最终文本时使用打印模式，包括命令替换、管道和一次性任务。中间事件不会暴露。

打印模式将错误写入 stderr。最终助手响应的停止原因为 error 或 aborted 时会产生非零退出状态。在模型输出 token 上限处被截断的响应（length 停止原因）仍会将部分文本打印到 stdout，向 stderr 写入警告，并产生非零退出状态。

未显式选择模式时，非 TTY 的 stdin 或 stdout 也会选择打印模式。这样无需加 --print 即可使用管道输入输出。

流式输出 JSON 事件 ​

JSON 模式先写入会话头，然后将 agent 和会话事件以换行分隔的 JSON 输出：

bash
pi --mode json "Review this repository" > events.jsonl

这是结构化的事件输出，不是单个 JSON 结果，也不限制模型响应的格式。

所有提示词在进程启动时提供。进程为该次运行流式输出事件后退出；它不接受后续命令。

失败或中止的助手响应会出现在事件流中，但本身不会产生非零退出状态。当成功与否很重要时，请检查事件。如果调用本身抛出错误，Pi 仍会以非零状态退出。

流式的 message_update 记录包含增量（delta）而非不断增长的消息快照。从增量事件组装实时输出，然后用 message_end 中的权威消息替换它。

agent_end 之后可能有自动恢复或排队工作。agent_settled 标记当前运行自动工作的结束。

stdout 保留给 JSONL。诊断和应用日志写入 stderr。帧格式、事件形态和重建规则参见 JSON 事件流。

用 RPC 控制 Pi ​

RPC 模式让 Pi 保持运行，同时另一个进程发送命令并接收响应和事件：

bash
pi --mode rpc --no-session

命令是写入 stdin 的 JSON 对象。响应和事件是写入 stdout 的 JSON 对象。每条记录占一行。

为需要关联的命令添加 id。对应的响应会重复该 ID。事件通常没有命令 ID，因为它们描述的是会话活动而非单个请求。

成功的 prompt 响应表示提示词已被接受、排队或处理，不代表运行已完成。当完成与否很重要时，继续消费事件直到 agent_settled。

RPC 命令可以切换模型、检查状态、管理会话、运行 shell 命令，以及响应扩展（extension）UI 请求。

扩展对话框构成一个请求-响应子协议。其他扩展 UI 更新是通知，客户端可以选择显示或忽略。仅限 TUI 的扩展能力在非交互模式下不可用或降级。

对于 Node.js 或 TypeScript 集成，优先使用 @earendil-works/pi-coding-agent 的 RpcClient。它启动一个 Pi RPC 子进程，关联请求，提供带类型的命令方法，并向监听器分发会话事件。

RPC 客户端示例发送一条提示词，流式输出文本和工具活动，等待 agent_settled，然后关闭子进程。该示例包含在仓库的 TypeScript 检查中。

RpcClient.promptAndWait() 在发送提示词之前安装事件监听器，避免与快速完成产生竞态。对于分离的操作，在调用 prompt() 之前订阅，并仅在运行进行中调用 waitForIdle()。

客户端需要一个可运行的 Pi CLI 路径。仓库示例指向 dist/cli.js，因此在 checkout 中运行该示例前必须先构建包。

如果你在不使用 RpcClient 的情况下构建客户端，请先阅读 RPC 协议，再用 RPC 命令 和 JSON 事件流 作为协议参考。

分叉与更改品牌 ​

源码分叉（fork）可以通过 package.json 更改 CLI 名称和配置目录：

json
{
  "piConfig": {
    "name": "my-agent",
    "configDir": ".my-agent"
  }
}

修改顶层 bin 字段以设置可执行文件名。这些设置会影响 CLI 横幅、配置路径和派生的环境变量名。
