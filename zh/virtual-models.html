虚拟模型 ​

虚拟模型（virtual model）是一种可选的模型，它为每个请求挑选一个物理模型。可用它按任务、费用或会话状态进行路由。例如，路由器可以把简单问题发给小模型、把困难问题发给大模型，而用户只需选择一个模型。

虚拟模型通过扩展注册。它们与其他模型一样出现在 /model、--model、作用域模型和设置中。虚拟模型可以列在任何提供商（provider）下，包括拥有物理模型的 provider，例如 openai-codex/auto。

选择与分发 ​

虚拟模型选择一个模型和一个思考级别。路由器为每个请求将这对组合映射到物理组合：

selected (virtual model, virtual level)  ->  dispatched (physical model, physical level)
jev/auto:low                             ->  anthropic/claude-sonnet-4-5:high

虚拟思考级别是路由器的输入。其含义由路由器决定，不必对应推理预算（reasoning budget）。

Pi 将两对组合分开保存：

选择分发
记录在model_change 和 thinking_level_change 条目每条助手消息：provider、api、model、thinkingLevel
可见为ctx.model、ctx.thinkingLevel、PI_MODEL、PI_REASONING_LEVEL、/model每次响应的助手消息

Provider 只接收物理模型。助手消息写明物理模型，因此在不同的物理模型之间重放会话与手动切换模型后的效果相同。恢复会话时，Pi 从最新的 model_change 条目还原虚拟选择。如果虚拟模型已不再注册，Pi 回退到最后应答的物理模型。

交互模式下，页脚在选择旁显示路由到的模型，例如 auto • high → gpt-5.6-luna • medium。/session 列出每个物理模型的费用。

上下文用量使用产生最近一次响应的物理模型的限制，即使该响应发生在切换到虚拟模型之前。没有这样的响应时，使用虚拟模型声明的限制（如有）。压缩（compaction）检查相同的限制，同样是每个请求被路由到的模型的限制。如果该模型的上下文窗口太小装不下对话，Pi 会在发送请求前进行压缩；路由保持路由器的选择不变。

注册虚拟模型 ​

typescript
import type { ExtensionAPI } from "@earendil-works/pi-coding-agent";

export default function (pi: ExtensionAPI) {
  pi.registerVirtualModel({
    provider: "router",
    id: "auto",
    name: "Auto",
    thinkingLevels: ["low", "high"],
    route(request, ctx) {
      // 工具后续调用和重试保持在处理该回合的模型上。
      const sticky = request.failed ?? request.previous;
      if (request.reason !== "user" && sticky) {
        return { model: sticky.model, thinkingLevel: sticky.thinkingLevel ?? "medium" };
      }
      const id = request.thinkingLevel === "high" ? "claude-sonnet-4-5" : "claude-haiku-4-5";
      return { model: ctx.modelRegistry.find("anthropic", id)!, thinkingLevel: "medium" };
    },
  });
}
  • provider 是模型列在其下的 provider。可以是任意 provider ID。一个 provider 可以在其物理模型旁列出多个虚拟模型。在物理 provider 上，该 provider 有凭据时虚拟模型才可用；在没有 provider 使用的 ID 下则始终可用。
  • id 不能是该 provider 的某个物理模型的 ID。如果之后的目录刷新添加了同 ID 的物理模型，虚拟模型会将其隐藏。
  • thinkingLevels 列出可供选择的级别。默认为 ["off"]。
  • contextWindow 和 maxTokens 在第一次响应之前显示。未设置的限制视为未知。
  • input 列出可供选择的输入类型。默认为文本和图片；不支持图片的物理模型会收到占位符。

注册遵循与 pi.registerProvider() 相同的排队和重载规则。再次注册相同的 provider 和 ID 会替换虚拟模型。pi.unregisterVirtualModel(provider, id) 移除它；pi.unregisterProvider() 不会。SDK 代码无需扩展即可注册：modelRuntime.registerVirtualModel(definition)。

路由请求 ​

route(request, ctx) 在使用虚拟模型的每个请求前运行，并返回 { model, thinkingLevel }。模型可以是目录中任何其 provider 拥有凭据的物理模型；用 ctx.modelRegistry 查找。虚拟模型不能路由到另一个虚拟模型。Pi 会将思考级别钳制（clamp）到返回的模型所支持的级别。

字段含义
model、thinkingLevel选定的虚拟模型和级别
reason发起请求的原因，见下文
previousmessages 中最近一次成功响应的物理模型和思考级别
failed对 retry：失败请求的物理模型、思考级别和助手 message，messages 中已不包含该消息。消息带有 stopReason 和 errorMessage。路由本身失败时不存在
state该会话分支上最近返回的路由器状态，见下文
messages本次请求的对话，包括系统消息
signal请求的中止信号（abort signal）
reason请求
user用户写入消息后的第一个请求，包括引导（steering）和后续（follow-up）消息
continuationagent 循环中的其他请求，例如工具结果或扩展消息之后
retry请求失败后的自动重试，包括上下文溢出后压缩（compaction）之后的重试
directagent 循环之外的请求，例如压缩摘要或扩展调用 ctx.modelRegistry.streamSimple()

对 continuation 返回 previous、对 retry 返回 failed，可以保持提示词缓存（prompt cache）和思考签名（thinking signatures）有效。回合之间切换模型是允许的，但会失去提示词缓存。重试也可以切换到另一个模型，例如当 failed.message.errorMessage 报告 provider 过载或上下文溢出时。

如果 route() 抛出异常，或返回虚拟模型或没有凭据的模型，请求以错误响应结束。

保存路由状态 ​

route() 可以在模型旁返回 state。Pi 将它存储在会话分支上，并在后续请求中作为 request.state 传回。用它保存转录中没有记录的决策依据，例如分类器结果或路由阶段：

typescript
pi.registerVirtualModel<{ phase: "plan" | "build" }>({
  provider: "router",
  id: "phased",
  name: "Phased",
  route(request, ctx) {
    const state = request.state ?? { phase: "plan" };
    const id = state.phase === "plan" ? "claude-opus-4-5" : "claude-haiku-4-5";
    return { model: ctx.modelRegistry.find("anthropic", id)!, thinkingLevel: "medium", state };
  },
});
  • 状态必须可 JSON 序列化。返回 undefined 或 request.state 本身会保持当前状态。
  • Pi 会将返回的其他任何对象存储为新状态，存储发生在请求发送之前，即使它等于当前状态。只在状态变化时返回新对象。请求稍后失败时状态仍然保留。
  • 状态跟随会话树，因此分叉（fork）和 /tree 导航看到的是各自分支的状态。它可以在压缩后保留。
  • direct 请求没有状态，Pi 也会忽略它们返回的状态。

转录已经记录了选择和每次分发的模型，ctx.sessionManager.getBranch() 会暴露这两者。

路由器可以通过 ctx.modelRegistry 调用其他模型，例如用 ctx.modelRegistry.findOfType("classifier", provider, id) 得到的分类器模型调用 ctx.modelRegistry.classify()。该调用会在回合的第一个 token 之前增加延迟。

完整路由器见 jev-router.ts。它在由 Jev 分类器选出的强 OpenAI Codex 模型上做规划，让该模型完成第一次编辑，然后切换一次到更便宜的模型，接受一次提示词缓存未命中。它将阶段保存为路由器状态。
