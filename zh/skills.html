技能 ​

技能（skill）为 Pi 提供针对特定工作类型的专门指令和配套文件。Pi 以名称和描述宣传每个可用技能，只在任务需要时才加载完整指令。

当工作流需要的上下文超出提示词模板（prompt template）的承载能力，但又不需要新的可执行集成点时，使用技能。技能可以在指令之外捆绑脚本、参考资料和资产。

Pi 实现了 Agent Skills 规范。大多数无效字段只产生警告，不会阻止启动。

创建技能 ​

技能是一个包含 SKILL.md 的目录：

text
pdf-tools/
├── SKILL.md
├── scripts/
│   └── extract.sh
├── references/
│   └── formats.md
└── assets/
    └── template.json

SKILL.md 以 frontmatter 开头，后接直接指令：

markdown
---
name: pdf-tools
description: Extract text and tables from PDF files. Use when reading, converting, or inspecting PDFs.
---

# PDF tools

Read `references/formats.md` before converting a document. Run scripts relative to this skill directory.

描述决定了模型何时考虑加载该技能。既要说明技能做什么，也要说明它适用于何时。避免使用"Helps with PDFs"这类缺乏路由信息的描述。

引用捆绑文件时使用相对于技能目录的路径。Pi 会告知模型技能所在位置，以便解析这些路径。

了解技能如何加载 ​

启动时，Pi 扫描已配置的技能位置，并将每个技能的名称、描述和路径加入系统提示词，但不会加入完整指令。

当任务匹配时，模型会读取 SKILL.md 并遵循其指令。这使详细指引在需要之前不占用上下文。模型可能未能加载相关技能，因此需要强制加载时使用 /skill:name。

/skill:name 之后的参数会作为用户请求附加到已加载的指令后：

text
/skill:pdf-tools extract report.pdf

当技能只应通过其显式命令使用时，在 frontmatter 中设置 disable-model-invocation: true。enableSkillCommands 设置控制技能命令是否出现在交互式命令发现中；手动输入的 /skill:name 命令仍然有效。

将技能加入 Pi ​

将技能放入你的用户级或项目级技能目录。包含 SKILL.md 的目录会被递归发现。

Pi 还支持 Agent Skills 位置 ~/.agents/skills/ 和 .agents/skills/。项目的 .agents/skills/ 目录从工作目录沿祖先目录向上发现，遇到仓库根目录（如果存在）即停止。

Pi 也接受部分独立的 Markdown 技能文件，但包含 SKILL.md 的目录是可移植的形式，应优先使用。更多位置见设置和 Pi 包。

项目技能可以指示模型运行脚本或修改文件。授予项目信任前，请审查不熟悉的技能及其配套文件。

编写可移植的 frontmatter ​

Agent Skills 规范定义了以下字段：

字段用途
name命令名和显示名
description展示给模型的路由描述
license许可证名称或捆绑的许可证文件
compatibility环境要求
metadata额外的键值元数据
allowed-tools实验性的预批准工具列表
disable-model-invocation对模型的自动选择隐藏该技能

名称使用小写字母、数字和连字符，不允许开头、结尾或连续的连字符。名称最多 64 个字符；描述最多 1024 个字符。

当声明的名称与父目录不一致时，Pi 既不强制要求也不发出警告。其他 Agent Skills 实现可能强制该要求，因此保持名称一致仍是更可移植的选择。

格式错误的 SKILL.md 文件和没有描述的已声明技能不会被加载。名称冲突时保留第一个发现的技能并产生警告。

验证和分享技能 ​

在技能可被发现的位置运行 Pi，然后检查启动诊断信息和 /skill:name 命令。会话进行中编辑技能后运行 /reload。

使用 Pi 包通过 npm 或 git 分发一个或多个技能。将环境配置保留在技能内部，并在包中声明所需的运行时依赖。

示例见 Anthropic 技能集合和 Pi 技能集合。
