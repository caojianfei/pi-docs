终端 UI ​

@earendil-works/pi-tui 提供了 Pi 所使用的终端组件系统。当内置的对话框、通知、状态文本和组件无法满足所需的交互时，扩展（extension）可以使用它。

从扩展中的 ctx.ui 方法入手。只有当 UI 需要自己的渲染、键盘或鼠标输入、焦点、布局或生命周期时，才构建自定义组件。

选择集成点 ​

需求使用
选择、确认、输入或多行编辑器ctx.ui.select()、confirm()、input() 或 editor()
非阻塞反馈ctx.ui.notify() 或 setStatus()
编辑器附近的持久内容ctx.ui.setWidget()
替换页眉、页脚或编辑器对应的 ctx.ui 组件工厂
临时交互屏幕或覆盖层ctx.ui.custom()
工具或会话条目的自定义渲染扩展渲染器（extension renderer）

这些 API 会在需要时接收 Pi 当前激活的主题和快捷键绑定。不要在扩展内部创建第二个终端渲染器。

理解组件模型 ​

组件针对给定宽度渲染一组终端行。它可以可选地处理键盘和鼠标输入，并且必须在自身状态或依赖主题的内容变化时使缓存的输出失效。

每条渲染的行必须适配给定的宽度。应测量可见的终端列数而不是字符串长度，因为 ANSI 转义序列、宽字符、emoji 和组合字符都会改变显示宽度。

使用 visibleWidth()、truncateToWidth()、sliceByColumn() 和 wrapTextWithAnsi()，不要自行实现终端宽度处理。Pi 会在每行之后重置样式和超链接，因此要在每条渲染的行上重新应用样式。

修改组件状态后，使受影响的组件失效并调用注入的 tui.requestRender()。TUI 会合并渲染请求并更新终端。

组合内置组件 ​

该软件包包含用于常见布局和控件的组件：

  • Text、Markdown、Image 和 TruncatedText 渲染内容。
  • Container、VStack、HStack、Box 和 Spacer 组合布局。
  • Input 和 Editor 接收文本。
  • SelectList 和 SettingsList 实现可搜索的选择和设置流程。
  • ScrollView 提供有界的可滚动视口。
  • Loader 和 CancellableLoader 报告进行中的工作。
  • MouseRegion 为其他组件添加指针行为。

优先使用这些组件，而不是重新实现选择、滚动、文本编辑或宽度处理。扩展示例展示了如何将它们与 Pi 的边框和主题结合使用。

处理键盘输入和焦点 ​

终端键盘输入使用 matchesKey() 和 Key。解析器会考虑受支持的终端协议和按键修饰符。扩展组件应使用注入的 KeybindingsManager 处理可配置的应用操作。

显示文本光标的组件应实现 Focusable，并将 CURSOR_MARKER 放在视觉光标紧前的位置。将光标单元格包裹在 renderFakeCursor() 中，TUI 会以反色（reverse video）绘制它，或在显示硬件光标时隐藏 CURSOR_MARKER 之后的区域。TUI 使用该标记为输入法编辑器定位硬件光标。

包裹 Input 或 Editor 的容器必须将自身的 focused 状态传播给该子组件。如果不传播，中文、日文、韩文等输入法候选窗可能出现在错误的屏幕位置。

替换主编辑器时应扩展 Pi 的 CustomEditor。它保留了应用快捷键和 agent 控件。

将编辑器不拥有的按键转发给基类实现，并通过清除自定义编辑器工厂来恢复默认值。

处理鼠标输入 ​

全屏模式将归一化的鼠标事件路由到组件。处理器可以标记事件已处理、捕获拖动序列、请求焦点或请求渲染。

未处理的滚轮事件会滚动最近的 ScrollView。未处理的主键拖动仍可用于转录（transcript）选择。OSC 8 链接优先于外层的点击区域。

常规模式将鼠标输入留给终端，因为终端拥有滚动缓冲区（scrollback）。即使全屏鼠标输入可用，也要为每种交互设计键盘路径。

使用自定义屏幕和覆盖层 ​

ctx.ui.custom() 临时让一个组件接管交互区域，并在该组件调用提供的完成回调时 resolve。

构建一个最小自定义屏幕 ​

这个完整的扩展示例展示了自定义组件的生命周期：在给定宽度内渲染、使用注入的快捷键、状态变化后使缓存输出失效、请求渲染，并通过 done() 结束。

typescript
import type { ExtensionAPI } from "@earendil-works/pi-coding-agent";
import { truncateToWidth } from "@earendil-works/pi-tui";

export default function (pi: ExtensionAPI) {
  pi.registerCommand("pick-target", {
    description: "Pick a deployment target",
    handler: async (_args, ctx) => {
      if (ctx.mode !== "tui") {
        ctx.ui.notify("pick-target requires interactive mode", "error");
        return;
      }

      const choices = ["development", "staging", "production"];
      const selected = await ctx.ui.custom<string | undefined>((tui, theme, keybindings, done) => {
        let selectedIndex = 0;
        let cachedWidth: number | undefined;
        let cachedLines: string[] | undefined;

        const invalidate = () => {
          cachedWidth = undefined;
          cachedLines = undefined;
        };

        return {
          render(width: number): string[] {
            if (cachedLines && cachedWidth === width) return cachedLines;

            cachedWidth = width;
            cachedLines = [
              theme.fg("accent", "Choose a deployment target"),
              ...choices.map((choice, index) => `${index === selectedIndex ? "> " : "  "}${choice}`),
              theme.fg("dim", "up/down move, enter selects, escape cancels"),
            ].map((line) => truncateToWidth(line, width));
            return cachedLines;
          },
          handleInput(data: string): void {
            if (keybindings.matches(data, "tui.select.up")) {
              selectedIndex = (selectedIndex - 1 + choices.length) % choices.length;
            } else if (keybindings.matches(data, "tui.select.down")) {
              selectedIndex = (selectedIndex + 1) % choices.length;
            } else if (keybindings.matches(data, "tui.select.confirm")) {
              done(choices[selectedIndex]);
              return;
            } else if (keybindings.matches(data, "tui.select.cancel")) {
              done(undefined);
              return;
            } else {
              return;
            }

            invalidate();
            tui.requestRender();
          },
          invalidate,
        };
      });

      if (selected) ctx.ui.notify(`Selected ${selected}`, "info");
    },
  });
}

此组件不显示文本光标，因此不需要 Focusable。包含 Input 或 Editor 的组件必须实现 Focusable，并将其 focused 值传播给该子组件。

传入 overlay: true 可在现有内容之上绘制。覆盖层（overlay）选项控制大小、锚点、偏移、边距和响应式可见性。覆盖层句柄可以在交互保持活跃的同时更改焦点，或通过 setHidden() 临时隐藏和显示覆盖层。

持有焦点的覆盖层在普通渲染之间保留输入所有权。如果覆盖层仍然可见而另一个组件需要接收输入，请通过句柄显式释放或转移焦点。

将每个自定义组件实例视为属于一次交互。再次开始该交互时创建新实例。

用提供给组件工厂的完成回调结束交互。它会 resolve ctx.ui.custom() 的 promise 并销毁组件。不要对由 ctx.ui.custom() 创建的覆盖层调用 OverlayHandle.hide()。

定位、堆叠、焦点、响应式可见性和动画行为见 overlay-qa-tests.ts。

正确应用主题 ​

使用传递给扩展或组件回调的主题。主题辅助函数为语义颜色（如 accent、次要文本、成功、警告、错误、工具输出和 Markdown）生成带 ANSI 样式的字符串。

使用 theme.style() 将前景色和背景色与文本属性组合：

typescript
return new Text(
  theme.style("Done!", {
    fg: "success",
    bg: "toolSuccessBg",
    bold: true,
  }),
  0,
  0,
);

样式颜色可以是语义主题令牌（token）或具体的 Color。前景令牌可作为 fg，背景令牌可作为 bg；要在另一个位置使用令牌的颜色，传入其具体颜色，例如 { fg: theme.colors.userMessageBg }。通过 theme.colors 访问具体颜色，需要颜色计算时使用 @earendil-works/pi-tui 提供的 mixColors() 等工具。主题设为终端默认值的令牌按终端自身的颜色渲染；theme.colors 报告终端宣告的颜色，未宣告时给出猜测值。使用 theme.appearance（"dark" 或 "light"）来决定例如加亮还是加深某个颜色。Pi 根据终端能力将结果转换为真彩色或 256 色输出。主题令牌在每个主题中只转换一次；尽量在渲染路径之外计算具体颜色。

现有的 theme.fg() 和 theme.bg() 辅助函数仍可用于应用单个语义颜色。

除非 invalidate() 会重建它们，否则不要永久存储带主题颜色的字符串。主题变化会清空渲染缓存，但无法移除嵌入在应用状态中的旧 ANSI 颜色。

渲染期间求值的主题回调不需要特殊重建。无状态组件也可以在每次渲染时计算带主题的输出。

终端配色使用主题创建。渲染需要与应用主题一致的 Markdown 时，使用 Pi 的 getMarkdownTheme()。

保持渲染响应迅速 ​

渲染在交互路径上运行。按宽度和内容缓存昂贵的布局和高亮工作，并在 invalidate() 中清除该缓存。

保持默认视图紧凑，通过展开或专用屏幕显示细节。对于自定义工具渲染，要处理部分结果，并在可安全更新时复用之前的组件。

诊断渲染问题时，使用 PI_TUI_WRITE_LOG 捕获原始 ANSI 流。测试窄宽度、宽字符、resize 事件、主题变化、焦点切换，以及常规和全屏两种模式。
