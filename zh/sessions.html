会话与上下文 ​

Pi 将对话保存为会话（session）。该会话的活跃分支为下一次模型请求提供对话历史。使用会话命令可以继续工作、探索其他分支，或减少发送给模型的历史量。

继续或切换会话 ​

Pi 会自动保存会话，除非使用 --no-session 启动。

bash
pi --continue
pi --resume

--continue 打开当前工作目录最近的会话。--resume 打开会话选择器。在交互模式中，/resume 打开同一个选择器，/new 开启新会话。

使用 /name 或 --name 为会话指定一个易于识别的名称。运行 /session 可查看当前会话文件、ID、消息数、token 用量和费用。

会话选择器支持搜索、重命名和删除会话，还可以显示路径、更改排序，以及只显示已命名的会话。其快捷键见快捷键。

选择分支方式 ​

Pi 将条目存储为树，因此返回较早的位置不会抹掉你离开的分支。

操作结果适用场景
/tree在当前会话文件内移动相关的备选方案应放在一起
/fork从较早的用户消息创建新会话备选方案应成为独立的工作
/clone将活跃分支复制到新会话需要当前状态的独立副本时

在 /tree 中，选中一条用户消息可将其文本放回编辑器。编辑并提交即可创建另一个分支。选中助手响应或其他条目则从该条目之后继续，编辑器为空。

离开一个分支时，Pi 可以对它进行摘要，并将该摘要附加到你进入的分支上。这样既保留了被放弃路径中的相关内容，又不必包含其中的每条消息。

持久化的树和条目类型见会话文件格式。

管理对话上下文 ​

模型接收的是活跃分支，而不是会话文件中的所有分支。Pi 将这段历史与系统提示词、发现的上下文文件、可用工具和已加载的技能（skill）描述组合在一起。Pi 的工作原理描述了这些输入如何组装。

底部状态栏显示当前上下文用量。当活跃上下文接近模型上限时，Pi 通常会自动压缩（compaction）较旧的历史。压缩会添加一条摘要并保留最近的消息，但不会删除原始会话条目。

运行 /compact 可手动压缩。当摘要需要保留特定主题或决策时，可以附加指令。通过设置配置自动压缩和保留的历史。

如果提供商（provider）不可用或无法接受摘要请求，压缩可能失败。解决提供商问题后再次运行 /compact。禁用自动压缩不会禁用手动命令。

阈值、保留边界、分支摘要行为和扩展钩子见压缩参考。

控制会话存储 ​

默认情况下，Pi 将会话存储在 ~/.pi/agent/sessions/ 下，按工作目录分组。使用 --session-dir、PI_CODING_AGENT_SESSION_DIR 或 sessionDir 设置可选择其他位置。CLI 选项的优先级最高。

临时运行使用 --no-session。临时会话在 Pi 退出后无法恢复。

已知会话路径或 ID 时使用 --session。使用 --fork 可在交互模式开始前从现有会话创建新会话。

导出或分享会话 ​

使用 /export 可将当前会话导出为 HTML 或 JSONL。使用 /share 可上传会话并获得查看链接。默认情况下，已配置 Radius 认证时 Pi 使用 Radius artifact，否则使用私有的 GitHub gist。将 sessionShareDestination 设为 gist 或 radius 可强制指定目的地。

导出或分享之前请先检查会话内容。其中可能包含提示词、模型响应、工具参数、命令输出、文件内容和扩展消息。

报告 bug ​

运行 /bug [description] 可为 Pi 开发者准备一份私密报告。你可以包含会话记录、省略它，或让当前模型总结问题。请检查记录或生成的摘要，因为其中可能包含敏感的对话数据。

报告包含环境和提供商配置（不含凭据值），以及记录的错误诊断。通过 radius.pi.dev 上传，或导出同一报告的 zip 自行检查和分享。上传无需登录；Radius 认证会将报告归属到你的账户，便于开发者跟进。如果上传失败，Pi 会提供导出 zip 的选项。
