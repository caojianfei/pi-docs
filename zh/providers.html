提供商 ​

大多数托管提供商（provider）支持以下一种或两种认证方式：

  • 通过基于 OAuth 的浏览器或设备流程登录。
  • 提供 API key。

使用 /login [provider] 查看某个提供商支持的方式。Amazon Bedrock 和 Google Vertex AI 还可以使用环境云凭据。

交互式认证 ​

运行 /login 并选择一个提供商。Pi 会引导你完成其 OAuth 或 API key 流程，并将得到的凭据保存在 auth.json 中。

在远程或无界面（headless）机器上，OAuth 回调可能无法到达本地进程。收到提示时，将最终重定向 URL 或授权码粘贴回 Pi。

运行 /logout 并选择一个提供商，可移除其已保存的凭据。这不会取消设置环境变量、不会移除 models.json 中的认证，也不会在提供商侧撤销凭据。

auth.json 可以包含 API key 和 OAuth token。请妥善保管，不要提交到版本库。

从环境变量使用 API key ​

环境变量适用于 CI 以及任何不应由 Pi 保存 key 的场景。在启动 Pi 之前设置变量：

bash
export ANTHROPIC_API_KEY=sk-ant-...
pi

下表涵盖只有一个主要 API key 变量的提供商。需要额外配置或支持环境凭据的提供商见特定提供商配置。

从命令加载 API key ​

要在不把解析后的 key 写入磁盘的情况下使用密钥管理器，将 auth.json 中提供商的 key 设为以 ! 为前缀的命令：

json
{
  "anthropic": {
    "type": "api_key",
    "key": "!security find-generic-password -ws 'anthropic'"
  }
}

Pi 在首次需要 key 时运行该命令，并在进程生命周期内缓存其标准输出。输出为空、超时或非零退出都会使 key 保持未解析状态，直到 Pi 重启。

特定提供商配置 ​

以下提供商有额外的设置步骤、需要额外配置，或可以使用其平台提供的凭据。

已保存的 API key 凭据可以包含 env 对象。其值对该提供商优先于进程环境：

json
{
  "cloudflare-workers-ai": {
    "type": "api_key",
    "key": "...",
    "env": {
      "CLOUDFLARE_ACCOUNT_ID": "account-id"
    }
  }
}

Radius ​

Radius 是由 Pi 的打造者 Earendil Works 专为 Pi 打造的服务。它提供可定制的 AI 网关，内置组织级控制和分析功能，以及用于分享你在 Pi 中创作成果的制品（artifact）。

要开始使用，在 Pi 中运行 /login radius。这会将 Radius 添加为提供商，其模型会像其他提供商一样出现在 /model 中。

Radius 还提供 MCP server，Pi 可以为你管理 Radius。

Radius 目前处于早期 alpha 阶段，迭代很快。更多信息见 radius.earendil.com。

Radius 认证使用其网关目录，并缓存刷新后的模型元数据以供后续离线启动。在 models.json 中配置的自定义 Radius 网关使用自己的目录，而不继承公共的 radius.pi.dev 目录。

OpenRouter ​

使用 /login openrouter 或 OPENROUTER_API_KEY 认证。

使用 key 时，Pi 只列出该 key 可用的 OpenRouter 对话模型，并附带该 key 的上下文大小、最大输出和价格。这些信息来自 OpenRouter 的 /models/user 端点，反映了 OpenRouter 中设置的防护规则和提供商限制。图像模型和分类模型不会被过滤。

Pi 会在启动时（交互模式）、打开 /model 时、/login 之后以及 pi update --models 时在后台刷新列表。最后一次列表会被保存，供离线、pi -p 和 RPC 模式使用。在 /login 之外切换 key 后，上一个 key 的列表会保留到下次刷新。

区域端点会按区域过滤模型。要使用区域端点，在 models.json 中设置 base URL：

json
{
  "providers": {
    "openrouter": { "baseUrl": "https://us.openrouter.ai/api/v1" }
  }
}

如果 base URL 在 /models/user 上拒绝该 key 或没有该端点（例如被配置为 OpenRouter base URL 的代理），Pi 会列出所有 OpenRouter 模型。

Azure OpenAI ​

提供商 ID 是 azure（原 azure-openai-responses）。在 auth.json、models.json 和 settings.json 中，以及在 --model azure/gpt-5.4 等模型引用中使用它作为键。

azure 提供商通过 Responses API 提供 OpenAI 模型，通过 Chat Completions 提供 Microsoft Foundry 模型，例如 azure/deepseek-v4-pro。

设置 API key，外加 base URL 或资源名：

bash
export AZURE_OPENAI_API_KEY=...
export AZURE_OPENAI_BASE_URL=https://your-resource.ai.azure.com
# 或者：
export AZURE_OPENAI_RESOURCE_NAME=your-resource

ai.azure.com、cognitiveservices.azure.com 和 openai.azure.com 下的资源根 URL 会被规范化为 OpenAI API 路径。

Pi 将模型 ID 作为部署名发送。如果部署名不同，用 AZURE_OPENAI_DEPLOYMENT_NAME_MAP 映射：

bash
export AZURE_OPENAI_DEPLOYMENT_NAME_MAP=gpt-5.4=my-gpt-deployment,deepseek-v4-pro=my-deepseek

AZURE_OPENAI_API_VERSION 覆盖 OpenAI 模型的 API 版本（默认 v1）。

要使用 Pi 未内置的 Foundry 模型，在 models.json 的 azure 下添加，并设置 api: "openai-completions"。自定义模型需要 baseUrl；设置后，AZURE_OPENAI_BASE_URL 和 AZURE_OPENAI_RESOURCE_NAME 优先于它：

json
{
  "providers": {
    "azure": {
      "baseUrl": "https://your-resource.services.ai.azure.com",
      "models": [
        { "id": "your-deployment", "api": "openai-completions" }
      ]
    }
  }
}

Amazon Bedrock ​

Bedrock 可以使用 Bearer token 或环境中的 AWS 凭据来源：

bash
# 命名配置文件
export AWS_PROFILE=your-profile

# IAM 密钥
export AWS_ACCESS_KEY_ID=AKIA...
export AWS_SECRET_ACCESS_KEY=...
# 临时凭据必需
export AWS_SESSION_TOKEN=...

# Bedrock Bearer token
export AWS_BEARER_TOKEN_BEDROCK=...

# 区域，当配置文件或 AWS SDK 配置未提供时
export AWS_REGION=us-west-2
# 也支持 AWS_DEFAULT_REGION

Pi 还通过标准的 AWS_CONTAINER_CREDENTIALS_* 和 AWS_WEB_IDENTITY_TOKEN_FILE 变量支持 ECS 任务凭据和 IRSA。

Cloudflare AI Gateway ​

网关需要 token、account ID 和 gateway ID：

bash
export CLOUDFLARE_API_KEY=...
export CLOUDFLARE_ACCOUNT_ID=...
export CLOUDFLARE_GATEWAY_ID=...

account ID 和 gateway ID 可以来自进程环境或 auth.json 中凭据的 env 对象。

CLOUDFLARE_API_KEY 用于向网关认证 Pi。上游访问可以使用 Cloudflare 统一计费、存储在网关中的凭据，或在 models.json 中为该提供商配置的 Authorization header。

Cloudflare Workers AI ​

Workers AI 需要 token 和 account ID：

bash
export CLOUDFLARE_API_KEY=...
export CLOUDFLARE_ACCOUNT_ID=...

account ID 也可以保存在凭据的 env 对象中。

Google Vertex AI ​

使用 Google Cloud API key：

bash
export GOOGLE_CLOUD_API_KEY=...

要使用应用默认凭据（Application Default Credentials），配置项目和位置：

bash
export GOOGLE_CLOUD_PROJECT=your-project
# 也支持 GCLOUD_PROJECT
export GOOGLE_CLOUD_LOCATION=us-central1

然后认证：

bash
gcloud auth application-default login

要改用服务账号密钥文件，设置 GOOGLE_APPLICATION_CREDENTIALS 并同时设置项目和位置。
