在 Windows 上运行 Pi ​

Pi 可以作为原生 Windows 进程运行，也可以在适用于 Linux 的 Windows 子系统（WSL）中运行。原生 Windows 默认使用 Git Bash 执行 Bash 命令，并可选择向模型暴露 PowerShell。WSL 中的 Pi 使用 Linux 环境及其 Bash 安装。

安装和认证 Pi 请遵循主快速开始。本页用于选择和配置命令环境。

选择原生 Windows 还是 WSL ​

环境命令环境适用场景
原生 Windows + Git Bash内置 bash 工具和 ! 命令使用 Git Bash文件和开发工具主要在 Windows 上
原生 Windows + powershell 工具模型工具调用使用 PowerShell；! 命令仍可用 Bash任务依赖 PowerShell 模块或 Windows 原生命令
WSL所选 WSL 发行版中的 Linux Bash 和工具文件和工具链已经在 Linux 或 WSL 中

在原生 Windows 上使用 Git Bash ​

对大多数原生 Windows 用户来说，安装 Git for Windows 即可。

Pi 按以下顺序解析 Bash：

  1. ~/.pi/agent/settings.json 中的 shellPath
  2. %ProgramFiles%\Git\bin\bash.exe 的 Git Bash
  3. %ProgramFiles(x86)%\Git\bin\bash.exe 的 Git Bash
  4. PATH 上的 bash.exe，包括 Cygwin、MSYS2 或旧版 WSL Bash

启动 Pi 并输入以下命令验证 shell：

text
!printf 'Bash is working\n'

如果 Pi 找不到 Bash，它会报告检查过的位置。安装 Git for Windows、将其他 Bash 可执行文件加入 PATH，或配置 shellPath。

让模型使用 PowerShell ​

可选的 powershell 工具优先通过 pwsh.exe 运行命令，不可用时回退到 Windows PowerShell。它使用 -NoProfile -NonInteractive -ExecutionPolicy Bypass 启动 PowerShell。管理员强制执行的执行策略仍可能优先。

PowerShell 发现按以下顺序检查这些位置：

  1. PATH 上的 pwsh.exe
  2. %ProgramFiles%\PowerShell\7\pwsh.exe
  3. PATH 上的 powershell.exe
  4. %SystemRoot%\System32\WindowsPowerShell\v1.0\powershell.exe

要将面向模型的 bash 工具替换为 powershell，在 ~/.pi/agent/settings.json 中添加：

json
{
  "defaultTools": ["read", "powershell", "edit", "write"]
}

["-bash", "+powershell"] 效果相同，同时保留你配置的其他默认工具。

重启 Pi，然后让它运行一个无害的 PowerShell 命令。! 和 !! 编辑器命令仍使用 Bash。powershell 工具仅在 Pi 作为原生 Windows 进程运行时可用。

其他工具组合见设置。

WSL ​

Windows 上的 WSL 路径转换和 WSL 中额外的 Git 分支轮询识别 /mnt/<drive>，而不是自定义挂载根。

从 Windows 使用旧版 WSL bash.exe 启动器时，Pi 通过 stdin 发送命令，以避免命令行引号问题。

使用自定义 Bash 可执行文件 ​

当 Bash 安装在 Pi 无法自动发现的位置时，设置 shellPath：

json
{
  "shellPath": "C:\\cygwin64\\bin\\bash.exe"
}

命令前缀、别名和完整的 shell 解析行为见配置 shell 命令。

配置 Windows Terminal ​

Windows Terminal 会保留或改写一些修饰键。配置 Shift+Enter 和 Alt+Enter 见 Windows Terminal，Pi 的 Windows 和 WSL 快捷键默认值见快捷键。
