JSON 事件流 ​

JSON 模式为一次调用输出结构化进度：

bash
pi --mode json "Review this repository"

Pi 写入一个会话头，随后是会话事件，然后在提供的提示完成后退出。RPC 模式输出相同的会话事件结构，但没有会话头，因为它是双向、长期存在的协议。见 RPC 模式。

本页是 JSON 和 RPC 模式共享事件的权威参考。消息值使用共享消息类型。

帧格式与进程 I/O ​

流使用严格的 JSONL 帧。每条记录是一个以 LF（\n）结尾的 JSON 对象。只在 LF 处分割记录，并去掉可选的前置回车符。Unicode 行分隔符和段落分隔符在 JSON 字符串内是合法的，不是记录边界。

Node.js 的 readline 不适用于此流，因为它也会识别那些 Unicode 分隔符。应使用字节流或 UTF-8 流解码器，并在 LF 处分割。

持续读取 stdout。停止消费记录的读取器在管道缓冲区填满时会使 Pi 卡住。stdout 保留给 JSONL；诊断和应用日志输出到 stderr。

会话头 ​

JSON 模式的第一条记录是当前会话头：

json
{"type":"session","version":3,"id":"uuid","timestamp":"2024-12-03T14:00:00.000Z","cwd":"/path"}

RPC 模式不输出该记录。用 get_state 获取其当前会话 ID 和文件。

事件序列 ​

一次基本运行产生的记录如下：

json
{"type":"agent_start"}
{"type":"turn_start"}
{"type":"message_start","message":{"role":"user","content":"Review this repository","timestamp":1733234401000}}
{"type":"message_end","message":{"role":"user","content":"Review this repository","timestamp":1733234401000}}
{"type":"message_start","message":{"role":"assistant","content":[],"stopReason":"pending","...":"..."}}
{"type":"message_update","usage":{"...":"..."},"assistantMessageEvent":{"type":"text_delta","contentIndex":0,"delta":"Hello"}}
{"type":"message_end","message":{"role":"assistant","...":"..."}}
{"type":"turn_end","message":{"role":"assistant","...":"..."},"toolResults":[]}
{"type":"agent_end","messages":[{"...":"..."}],"willRetry":false}
{"type":"agent_settled","aborted":false}

agent_end 关闭一次底层 agent 运行。自动重试、溢出恢复、压缩重试、引导或后续工作仍可能继续。agent_settled 表示 Pi 对该会话级运行没有剩余的自动工作。

Agent 与轮次事件 ​

事件字段含义
agent_start无一次底层 agent 运行开始。
agent_endmessages、willRetry该底层运行结束。messages 包含该运行生成的消息。
agent_settledabortedPi 不会通过重试、压缩恢复或排队消息自动继续。当运行因被中止而结束时 aborted 为 true。
turn_start无一轮助手轮次开始。
turn_endmessage、toolResults一次助手响应及其产生的工具调用已完成。

一轮（turn）是一次助手响应，加上该响应产生的工具调用和工具结果。

消息事件 ​

事件字段含义
message_startmessage一条消息开始。
message_updateusage、assistantMessageEvent助手消息发出内容块更新。
message_endmessage一条消息完成。这是权威的最终消息。

重建流式消息 ​

线上的 message_update 记录只包含增量。它们省略 SDK 事件的累积 message 字段和所有 assistantMessageEvent.partial 快照，以保持流的大小线性。

嵌套事件是以下之一：

类型除 type 外的字段含义
start无Provider 流开始；其累积的 partial 字段在线上被移除。
text_startcontentIndex文本块开始。
text_deltacontentIndex、delta向该块追加文本。
text_endcontentIndex、content文本块以权威内容结束。
thinking_startcontentIndex思考块开始。
thinking_deltacontentIndex、delta向该块追加思考文本。
thinking_endcontentIndex、content思考块以权威内容结束。
toolcall_startcontentIndex、id、toolName工具调用块开始。
toolcall_deltacontentIndex、delta追加序列化的参数数据。
toolcall_endcontentIndex、toolCall工具调用以完整的 ToolCall 结束。
donereason、messageProvider 流成功完成。
errorreason、errorProvider 流以错误或中止消息结束。

正常的 agent 循环将 provider 级的 start、done 和 error 转换为 message_start 和 message_end 会话事件，而不是作为 message_update 输出。导出的 JsonAgentSessionEvent 转换仍然接受它们，供构造匹配会话事件的调用方使用。

用 contentIndex 标识内容块。缓冲 delta 字段用于实时显示，但在 text_end、thinking_end 或 toolcall_end 中用完成的内容替换重建的数据。当 message_end.message 到达时，用它替换整个部分消息。

顶层的 usage 是 provider 报告的助手响应的最新累积用量。当 provider 在流式期间不报告用量时，它在完成之前可能保持为零。

json
{"type":"message_update","usage":{"input":100,"output":1,"cacheRead":0,"cacheWrite":0,"totalTokens":101,"cost":{"input":0,"output":0,"cacheRead":0,"cacheWrite":0,"total":0}},"assistantMessageEvent":{"type":"text_delta","contentIndex":0,"delta":"Hello "}}

工具执行事件 ​

事件字段含义
tool_execution_starttoolCallId、toolName、args工具执行开始。
tool_execution_updatetoolCallId、toolName、args、partialResult工具报告了部分结果。
tool_execution_endtoolCallId、toolName、result、isError、durationMs工具执行结束。durationMs 是工具的 execute() 以单调时钟（monotonic clock）测得的耗时；工具未运行时缺省。

用 toolCallId 关联生命周期。partialResult 是工具提供的最新部分结果。它替换还是扩展先前的更新取决于该工具的结果契约。

json
{"type":"tool_execution_start","toolCallId":"call_abc123","toolName":"bash","args":{"command":"ls -la"}}
{"type":"tool_execution_update","toolCallId":"call_abc123","toolName":"bash","args":{"command":"ls -la"},"partialResult":{"content":[{"type":"text","text":"partial output"}],"details":{}}}
{"type":"tool_execution_end","toolCallId":"call_abc123","toolName":"bash","result":{"content":[{"type":"text","text":"complete output"}],"details":{}},"isError":false}

队列与状态事件 ​

事件字段含义
queue_updatesteering、followUp待处理的引导或后续队列发生变化。两个字段都包含完整的当前队列。
entry_appendedentry扩展通过 pi.appendEntry() 追加了自定义会话条目。
session_info_changedname会话显示名称发生变化。name 缺省表示被清除。
thinking_level_changedlevel活跃的思考级别发生变化。

entry 值使用持久化的会话条目类型。

压缩事件 ​

compaction_start 报告压缩开始的原因：

json
{"type":"compaction_start","reason":"threshold"}

reason 是 "manual"、"threshold" 或 "overflow"。

compaction_end 在压缩成功时包含结果：

json
{
  "type": "compaction_end",
  "reason": "threshold",
  "result": {
    "summary": "Summary of conversation...",
    "firstKeptEntryId": "abc123",
    "tokensBefore": 150000,
    "estimatedTokensAfter": 32000,
    "usage": {"...": "..."},
    "details": {}
  },
  "aborted": false,
  "willRetry": false
}

如果压缩被中止，result 缺省且 aborted 为 true。如果压缩失败，result 缺省、aborted 为 false，errorMessage 描述失败原因。成功的溢出恢复会在 Pi 重试提示之前将 willRetry 设为 true。

结果语义见压缩与分支摘要。

重试事件 ​

助手轮次重试会输出：

json
{"type":"auto_retry_start","attempt":1,"maxAttempts":3,"delayMs":2000,"errorMessage":"529 overloaded"}
{"type":"auto_retry_end","success":true,"attempt":2}

最终失败时，auto_retry_end 的 success 为 false 并带有 finalError 字符串。

压缩和分支摘要重试会输出：

json
{"type":"summarization_retry_scheduled","attempt":1,"maxAttempts":3,"delayMs":2000,"errorMessage":"terminated"}
{"type":"summarization_retry_attempt_start","source":"compaction","reason":"threshold"}
{"type":"summarization_retry_finished"}

分支摘要的 source 是 "branchSummary"，且没有 reason。压缩重试的 reason 是 "manual"、"threshold" 或 "overflow"。

仅限 RPC 的事件 ​

直接的 RPC bash 命令为每个输出块输出一条 bash_execution_update。其可选的 id 对应命令 ID。最终命令响应可能包含被截断的输出，但这些事件流式传输全部输出：

json
{"type":"bash_execution_update","id":"req-1","delta":"total 48\n"}

当扩展处理器抛出异常时，RPC 还会输出 extension_error：

json
{"type":"extension_error","extensionPath":"/path/to/extension.ts","event":"tool_call","error":"Error message"}

Extension UI 记录是一个独立的 RPC 子协议，不是 AgentSessionEvent 值。见 RPC Extension UI。

TypeScript 类型 ​

SDK 的 AgentSessionEvent 为进程内消费者包含累积的流式快照。JSON 和 RPC 只转换 message_update：

typescript
type WithoutPartial<T> = T extends { partial: unknown } ? Omit<T, "partial"> : T;

type JsonAssistantMessageEvent<T> = T extends { type: "toolcall_start"; partial: unknown }
  ? WithoutPartial<T> & { id: string; toolName: string }
  : WithoutPartial<T>;

type JsonAgentSessionEvent =
  | Exclude<AgentSessionEvent, { type: "message_update" }>
  | {
      type: "message_update";
      usage: Usage;
      assistantMessageEvent: JsonAssistantMessageEvent<AssistantMessageEvent>;
    };

使用从 @earendil-works/pi-coding-agent 导出的 JsonAgentSessionEvent 类型。其实现在 json-event.ts。

示例 ​

打印一次性运行中已完成的消息：

bash
pi --mode json "List files" 2>/dev/null | jq -c 'select(.type == "message_end")'
