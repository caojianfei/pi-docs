安全地运行 Pi ​

将模型生成的命令和代码视为不受信任的内容。Pi 能够以启动它的账户的权限读取、修改和执行文件，并且不会在每次工具调用前请求批准。扩展（extension）、包安装器、语言服务器和其他子进程都以相同的权限运行，除非有操作系统或虚拟化边界加以限制。

文件、注释、指令、命令输出和模型响应都可能通过提示词注入（prompt injection）左右模型的行为。项目信任（project trust）控制哪些项目资源在启动时加载，但它并不能使这些内容或由此产生的操作变得安全。

安全来自于限制 Pi 在某个生成的操作出错或带有恶意时能够访问和影响的文件、凭据、进程和网络服务。监视对话记录、使用项目信任、审查更改，这些都不构成安全边界。

选择运行 Pi 的方式 ​

不同的运行方式对生成命令可访问的内容施加不同的限制：

Pi 的运行方式仍受保护的内容
直接运行，拥有其操作系统用户的权限该用户无法访问的一切。专用的用户账户可以收窄这些权限，但 Pi 仍与其他用户共享操作系统和网络。
完全在容器、虚拟机或沙箱内运行你未暴露给该环境的宿主文件和进程。如果你把凭据和网络服务放进环境内部，它们仍可被访问。这通常是最强的实用选项。
在隔离环境之外运行，只有其内置工具在隔离环境内执行通过这些工具执行的操作无法触及宿主资源。Pi 本身和其他扩展仍在边界之外，因此这是一种较弱的隔离形式。

工作目录控制资源发现和工具的默认位置，但它不能阻止命令访问 Pi 进程可用的其他路径。

无论选择哪种方式，只提供任务所需的文件和服务。尽量把凭据放在环境之外，或使用范围狭窄、短期的凭据。命令不需要网络时，限制网络访问。

隔离方法的设置说明和局限，请参见在隔离环境中运行 Pi。

理解项目信任 ​

项目信任控制 Pi 是否加载由工作目录提供的大多数设置和资源。它可以防止一个目录在你批准之前静默加载可执行的扩展。

项目信任不是一个完整的启动边界。Pi 在选择或创建会话时会读取项目的 sessionDir 设置，而这发生在解析项目信任之前。拒绝信任可以阻止其余项目设置和受保护资源加载，但无法撤销那次初始的会话目录查找。

项目信任不限制工具调用可以访问或影响的内容。Pi 启动之后，已启用的工具仍然使用 Pi 进程的操作系统权限。目录中的指令和其他内容也会影响模型。

受项目信任保护的资源 ​

当 Pi 从当前工作目录发现以下任一资源时，会要求做出项目信任决定：

  • .pi/settings.json
  • .pi/mcp.json
  • .pi/extensions、.pi/skills、.pi/prompts 或 .pi/themes
  • .pi/SYSTEM.md 或 .pi/APPEND_SYSTEM.md
  • 当前目录或祖先目录中的项目 .agents/skills

仅存在一个空的 .pi 目录不需要项目信任。

授予项目信任后，Pi 可以加载：

  • 项目设置
  • 来自 .pi/mcp.json 的项目 MCP 服务器
  • .pi 下的扩展、技能、提示词模板、主题和系统提示词文件
  • 通过项目设置配置的缺失包
  • 项目本地扩展和项目包扩展

拒绝项目信任会跳过这些受保护的资源，但上述初始的 sessionDir 查找除外。

AGENTS.override.md、AGENTS.md 和 CLAUDE.md 等上下文文件无论项目信任与否都会加载，除非你禁用上下文加载。即使你拒绝了项目信任，也应将目录中的指令视为不受信任的输入。

Pi 如何做出信任决定 ​

命令行的 --approve 或 --no-approve 覆盖项优先。当存在受保护资源且没有命令行覆盖项时：

  1. 用户级和命令行扩展可以处理 project_trust 事件。第一个返回 yes 或 no 的扩展拥有该决定权。
  2. 如果没有扩展做出决定，Pi 会查找针对当前目录或其某个父目录已保存的决定。应用最近的决定。
  3. 如果没有适用的已保存决定，Pi 遵循全局的 defaultProjectTrust 设置，其默认值为 "ask"。

已保存的决定使用规范化的目录路径，存放在：

text
~/.pi/agent/trust.json

使用 /trust 为将来的 Pi 进程保存一个决定。

没有交互式提示时的项目信任 ​

打印（print）、JSON 和 RPC 模式无法显示内置的信任提示。如果没有命令行覆盖项、扩展或已保存的决定适用：

  • defaultProjectTrust: "always" 加载受保护的项目资源。
  • defaultProjectTrust: "ask" 或 "never" 跳过它们。

自动化运行需要明确的一次性决定时，使用 --approve 或 --no-approve。

降低影响并改善恢复 ​

以下做法不能替代隔离，但可以减少暴露面或让恢复更容易：

  • 只授予 Pi 完成任务所需的文件和服务访问权。
  • 在重大更改之前使用快照、备份或版本控制。
  • 在加载扩展和包之前先审查它们。扩展在 Pi 进程内部执行。
  • 优先使用范围狭窄、短期的凭据。
  • 在把结果应用到另一个系统之前，审查 diff 和生成的输出。
  • 在导出或分享会话之前先审查它们。会话中可能包含对话期间暴露的提示词、工具参数、命令输出、文件内容和凭据。

报告安全问题 ​

请遵循仓库的安全策略。安全敏感的报告不要开公开 issue。

本地 agent 的预期行为、来自不受信任内容的提示词注入、缺少内置沙箱，以及用户安装的扩展或技能引发的行为，通常不在安全边界之内——除非报告演示了权限边界绕过，或获得了本地用户原本不具备的访问权。
