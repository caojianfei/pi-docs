在隔离环境中运行 Pi ​

使用隔离环境可以限制生成的命令能够访问或影响的文件、凭据、进程和网络服务。

你可以把完整的 Pi 进程放入隔离环境，也可以让 Pi 留在宿主机上、把选定的工具路由到隔离环境中执行。

选择隔离方式 ​

方式Pi 运行位置隔离内容凭据处理适用场景
普通 Docker容器Pi、内置工具、! 命令和扩展凭据传入容器内简单直接的本地容器边界
Docker Sandboxes托管沙箱Pi、内置工具、! 命令和扩展提供商凭据保留在宿主机上，由代理替换托管式本地隔离，不暴露真实的提供商密钥
OpenShell本地或远程沙箱Pi、内置工具、! 命令和扩展由策略控制的凭据和推理路由文件系统、进程、网络和凭据策略
Gondolin 扩展宿主机内置工具和 ! 命令Pi 保存的凭据留在宿主机上，但命令继承宿主机环境变量本地微型 VM 执行工具，同时保留宿主界面

方式会影响扩展的运行位置。当完整 Pi 进程运行在隔离环境内时，其扩展也在其中运行。当宿主机 Pi 通过 Gondolin 委派内置工具时，其他扩展工具仍在宿主机上运行，除非它们也委派自己的工作。

决定 Pi 能访问什么 ​

被隔离的进程仍然可以影响你暴露给它的资源：

  • 读写挂载让 Pi 可以修改这些宿主机文件。
  • 挂载 ~/.pi/agent 会暴露你的 Pi 凭据、设置、扩展和会话。
  • 传入容器的环境变量对容器内的进程可用。
  • 网络访问可能让代码或工具输出离开隔离环境。
  • 仅隔离工具不会约束宿主机上的 Pi 进程，也不约束不使用隔离后端的扩展工具。

只暴露任务所需的工作目录、凭据和网络目标。如果不希望写入影响宿主机，使用只读挂载，或在环境内外复制文件。

在普通 Docker 中运行 Pi ​

普通 Docker 提供最简单的整进程容器边界。

构建镜像 ​

创建 Dockerfile.pi：

dockerfile
FROM node:24-bookworm-slim

RUN apt-get update \
  && apt-get install -y --no-install-recommends bash ca-certificates git ripgrep \
  && rm -rf /var/lib/apt/lists/*
RUN npm install -g --ignore-scripts @earendil-works/pi-coding-agent

WORKDIR /workspace
ENTRYPOINT ["pi"]

在该文件所在目录构建：

bash
docker build -t pi-sandbox -f Dockerfile.pi .

启动 Pi ​

在你想让 Pi 访问的工作目录中运行：

bash
docker run --rm -it \
  -e ANTHROPIC_API_KEY \
  -v "$PWD:/workspace" \
  -v pi-agent-home:/root/.pi/agent \
  pi-sandbox

把 ANTHROPIC_API_KEY 替换为你的提供商所需的凭据。命名卷 pi-agent-home 在多次运行之间保留容器本地的设置、凭据和会话。

除非容器需要访问宿主机的 Pi 配置和凭据，否则不要挂载宿主机的 ~/.pi/agent。

验证工作区 ​

在 Pi 内运行：

text
!pwd

命令应输出 /workspace。/workspace 下的更改会写入挂载的宿主机目录。如果不可接受，移除绑定挂载或改用只读挂载。

使用 Docker Sandboxes 运行 Pi ​

Docker Sandboxes 在托管沙箱内运行完整的 Pi 进程。其代理可以把真实的提供商凭据留在宿主机上，并在请求离开沙箱时替换凭据。

创建沙箱前先配置凭据。不要在沙箱内运行 /login，因为那会把真实凭据写入沙箱。

使用 Claude Pro 或 Max token ​

在有 Claude Code 的机器上用 claude setup-token 生成 token。如果已配置 anthropic secret，先移除它，避免代理在 bearer token 之外附加 API-key 头：

bash
sbx secret rm anthropic

sbx secret set-custom \
  --host api.anthropic.com \
  --env ANTHROPIC_OAUTH_TOKEN \
  --placeholder 'sk-ant-oat01-{rand}'

sbx secret set-custom 从标准输入读取真实 token。沙箱收到的是 OAuth 形状的占位符，代理只对发往所配置主机的请求替换它。

Anthropic API key 则改用 sbx secret set anthropic。

启动 Pi ​

在你想挂载的工作目录中运行：

bash
sbx run --kit "docker.io/sbx/pi-kit:latest" pi

对已有的沙箱，可以用以下命令非交互式运行 Pi：

bash
sbx exec <sandbox-name> -- pi -p "list the failing tests"

其他提供商、排障和镜像固定参见 Pi kit 文档。

使用 OpenShell 运行 Pi ​

NVIDIA OpenShell 提供带文件系统、进程、网络、凭据和推理策略的本地或远程沙箱。

选择网关 ​

每个沙箱都需要一个活跃的网关：

bash
openshell gateway add <gateway-url> --name <name>
openshell gateway select <name>

创建沙箱 ​

bash
openshell sandbox create --name pi-sandbox --from pi -- pi

Pi、其内置工具、! 命令和扩展工具都在 OpenShell 边界内运行。

向远程沙箱传输文件 ​

远程网关不会绑定挂载宿主机的工作目录。在沙箱内克隆仓库，或显式传输文件：

bash
openshell sandbox upload pi-sandbox ./working-folder /workspace
openshell sandbox download pi-sandbox /workspace/working-folder ./working-folder-out

OpenShell 的推理路由可以把原始模型凭据留在沙箱之外。配置后，将 Pi 指向网关暴露的相应 OpenAI 兼容或 Anthropic 兼容端点。

通过 Gondolin 路由工具 ​

Gondolin 是一个本地 Linux 微型 VM。它的示例扩展让 Pi 进程和基于文件的提供商凭据留在宿主机上，同时把内置工具和用户 ! 命令路由到 VM 内执行。

VM 内的命令继承宿主机进程的环境变量。因此通过环境变量提供的提供商密钥在 VM 内可见。除非移除敏感变量或修改扩展的环境处理方式，否则不要把这种模式当作凭据边界。

Gondolin 要求 Node.js 23.6 或更新版本，并通过操作系统包管理器安装 QEMU。

安装扩展 ​

在 Pi 源码检出目录中：

bash
mkdir -p ~/.pi/agent/extensions
cp -R packages/coding-agent/examples/extensions/gondolin ~/.pi/agent/extensions/gondolin
cd ~/.pi/agent/extensions/gondolin
npm install --ignore-scripts

启动 Pi ​

在你想挂载的工作目录中运行 Pi：

bash
cd /path/to/working-folder
pi -e ~/.pi/agent/extensions/gondolin

该扩展把宿主机工作目录挂载为 VM 内的 /workspace，并覆盖 read、write、edit、bash、grep、find 和 ls。/workspace 下的文件更改会写回宿主机。

其他扩展工具仍在宿主机上运行，除非它们显式委派自己的操作。在添加可能绕过 VM 边界的工具之前，先阅读 Gondolin 示例。
