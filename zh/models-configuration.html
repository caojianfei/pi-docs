模型配置 ​

本参考列出 models.json 的字段。示例参见配置兼容端点，文件位置参见配置。

在 models.json 中添加 "$schema": "https://pi.dev/schemas/models.schema.json" 以获得编辑器校验和补全。

提供商 ​

providers 下的每个键都是一个提供商（provider）ID。内置提供商 ID 会修改该提供商。其他 ID 则添加一个提供商，需要 baseUrl 以及提供商级或模型级的 api。

字段类型默认值说明
namestring显示名称。
baseUrlstringAPI 基础 URL。也适用于该提供商的内置模型。
apiKeystring字面量密钥、"$NAME" 环境变量插值，或 "!command" 命令输出。
apistring该提供商模型使用的 API，例如 "openai-completions"、"openai-responses"、"anthropic-messages" 或 "google-generative-ai"。
oauth"radius"OAuth 登录流程。需要 baseUrl。
headersobject请求头。值的解析方式与 apiKey 相同。
compatobject提供商和模型兼容性覆盖。
authHeaderbooleanfalse是否将解析后的 API 密钥作为 Authorization: Bearer 发送。
modelsobject[]
modelOverridesobject

兼容性 ​

compat 描述与 API 标准请求和响应行为之间已验证的差异。模型值按字段覆盖提供商值。适用哪些字段取决于模型的 api。

字段类型默认值说明
supportsStoreboolean提供商是否支持 store 字段。默认：从 URL 自动检测。
supportsDeveloperRoleboolean提供商是否支持 developer 角色而不是 system。默认：从 URL 自动检测。
supportsReasoningEffortboolean提供商是否支持 reasoning_effort。默认：从 URL 自动检测。

requiresToolResultNameboolean工具结果是否需要 name 字段。默认：从 URL 自动检测。
requiresAssistantAfterToolResultboolean工具结果之后的消息是否要求中间有 assistant 消息。默认：从 URL 自动检测。
requiresThinkingAsTextboolean思考块是否必须转换为带 <thinking> 分隔符的文本块。默认：从 URL 自动检测。
requiresReasoningContentOnAssistantMessagesboolean启用 reasoning 时，所有回放的 assistant 消息是否必须包含空的 reasoning_content 字段。默认：从 URL 自动检测。

chatTemplateKwargsobjectthinkingFormat 为 "chat-template" 时作为 chat_template_kwargs 发送的 kwargs。用 $var 配合 "thinking.enabled"、"thinking.effort" 或 "thinking.budget" 表示由 pi 控制的值。
chatTemplateArgsobjectthinkingFormat 为 "baseten" 时作为 chat_template_args 发送的参数。用 $var 配合 "thinking.enabled"、"thinking.effort" 或 "thinking.budget" 表示由 pi 控制的值。

vercelGatewayRoutingobjectVercel AI Gateway 路由偏好。控制网关将请求路由到哪些上游提供商。参见 https://vercel.com/docs/ai-gateway/models-and-providers/provider-options。
zaiToolStreambooleanfalsez.ai 是否支持顶层 tool_stream 用于流式工具调用增量。

也适用于 azure-openai-responses 和 openai-codex-responses。

字段类型默认值说明
supportsDeveloperRolebooleantrue提供商是否支持 developer 角色而不是 system。

supportsMaxOutputTokensbooleantrue提供商是否接受 max_output_tokens。某些 Codex 协议网关会拒绝它。
