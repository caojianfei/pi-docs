Pi 包 ​

Pi 包（package）将扩展、技能、提示词模板和主题作为一个整体进行安装和分发。当某项定制需要通过 npm 或 git 共享，或多个资源需要捆绑在一起时，使用包。

包就是一个普通的目录或 npm 包。它可以暴露约定俗成的资源目录、在 package.json 的 pi 键下声明显式路径，并携带自己的运行时依赖。

安装和管理包 ​

从 npm、git 或本地路径安装：

bash
pi install npm:@example/pi-tools@1.0.0
pi install git:github.com/example/pi-tools@v1
pi install ./local-package

pi list 显示已配置的包。使用 pi remove <source> 移除一个包，pi update --extensions 调整包的安装状态。所有包命令和选项见命令行。

如果已配置的包在启动时安装失败，例如 npm 无法访问 registry，Pi 会发出警告、跳过该包的资源并继续运行。Pi 会在下次启动或 /reload 时重试安装。pi install 和 pi update --extensions 仍会报告失败并以非零码退出。

个人安装写入 ~/.pi/agent/settings.json。添加 --local 或 -l 可将包声明写入 .pi/settings.json。Pi 只在授予项目信任后才读取该文件中的声明。

项目包只有在项目信任判定完成后才会安装和加载。包可以执行扩展代码，也可能包含指示模型运行程序的技能。安装第三方包之前请先审查其源码。授予项目信任之前请先审查项目包声明。

使用 --extension 或 -e 可以单次运行试用某个包，而不将其加入设置：

bash
pi -e npm:@example/pi-tools

选择来源 ​

来源示例行为
npmnpm:@example/pi-tools@1.0.0安装在 Pi 的 npm 目录下
gitgit:github.com/example/pi-tools@v1克隆并对齐到所选 ref
URLhttps://github.com/example/pi-tools视为 git 来源
本地./pi-tools从解析后的路径直接加载，不复制

带版本的 npm 规格会被固定（pin）。git 的 tag 和 commit 同样被固定；包更新只会调整检出状态，不会移动已配置的 ref。

相对本地路径相对于包含它的设置文件解析。文件路径加载一个扩展。目录遵循正常的包发现规则。

创建包 ​

最简单的包使用约定目录：

text
my-pi-package/
├── package.json
├── extensions/
├── skills/
├── prompts/
└── themes/

没有 pi 清单时，Pi 会从这些目录中发现 TypeScript 和 JavaScript 扩展、技能目录、Markdown 提示词和 JSON 主题。

当资源位于其他位置或需要过滤时，使用显式清单：

json
{
  "name": "my-pi-package",
  "keywords": ["pi-package"],
  "pi": {
    "extensions": ["./src/extension.ts"],
    "skills": ["./resources/skills"],
    "prompts": ["./resources/prompts/*.md"],
    "themes": ["./resources/themes/*.json"]
  }
}

路径相对于包根目录。数组支持 glob 模式和排除项。当 glob 遍历无法发现点前缀或符号链接的资源根目录时，直接列出它们。

pi-package 关键字使 npm 包有资格出现在 Pi 包画廊中。可选的 pi.image 和 pi.video 字段用于添加画廊预览。

声明依赖 ​

将扩展导入的运行时包放入 dependencies。Pi 在安装 npm 或 git 来源的包时会安装其依赖。

Pi 会向扩展和技能提供以下包：

  • @earendil-works/pi-ai
  • @earendil-works/pi-agent-core
  • @earendil-works/pi-coding-agent
  • @earendil-works/pi-tui
  • typebox

将上述宿主提供的包以 "*" 范围声明在 peerDependencies 中，并且不要打包它们。Pi 会抑制受管 npm 包以及通过 npm、pnpm 或 Bun 安装的 git 包的自动 peer 安装。本地包不会被安装或修改，因此其依赖树仍由包作者负责。

不要将宿主提供的包列入 dependencies。物理副本可能在编译后的 ESM 中绕过 Pi 的扩展模块映射，导致重复的类、注册表和初始化工作。Pi 检测到这种清单配置时会报告扩展警告。作为依赖使用的其他 Pi 包必须包含在发布的 tarball 中，并通过其 node_modules 资源路径引用。

已安装的包以独立的模块根加载。不要依赖两个包共享同一个依赖实例，也不要依赖一个包解析另一个包未声明的依赖。

选择包资源 ​

设置中的对象形式可以缩小从包中加载的资源：

json
{
  "packages": [
    {
      "source": "npm:@example/pi-tools",
      "extensions": ["extensions/*.ts", "!extensions/legacy.ts"],
      "skills": [],
      "prompts": ["prompts/review.md"]
    }
  ]
}

对每种资源类型：

  • 省略该属性以加载包允许的全部资源。
  • 使用 [] 表示不加载该类型。
  • 使用 !pattern 排除 glob 匹配项。
  • 使用 +path 精确包含一个允许的路径。
  • 使用 -path 精确排除一个路径。

过滤器只会收窄包清单，不会暴露包本身未声明的资源。

运行 pi config 可以启用或禁用发现的资源和 Pi 内置扩展。它从个人配置开始；按 Tab 切换作用域，或运行 pi config --local 以项目覆盖开始。

作用域与标识 ​

同一个包可以同时出现在个人设置和项目设置中。项目条目通常会替换个人条目。设置 autoload: false 时，项目条目改为作为对个人包的过滤增量。

Pi 通过包名标识 npm 包，通过不含 ref 的仓库 URL 标识 git 包，通过解析后的绝对路径标识本地包。这样可以防止同一个包通过等价声明被加载两次。

在打包之前，先用扩展、技能、提示词模板和主题设计好每个资源。
